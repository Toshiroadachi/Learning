今日は初めての**本格的なプロジェクト**です。トランプの「21（ブラックジャック）」を作ります。

ポイントは「全部を一度に書かない」こと。家を建てるときに、土台 → 柱 → 屋根と**部品ごとに作って確かめる**のと同じように、
1. スコアを計算する関数（ステップ1）
2. 勝ち負けを決める関数（ステップ2）
3. それらを使ってゲームを組み立てる（ステップ3）

と3段階で進めます。部品の関数がそれぞれ正しく動けば、組み立ても簡単になります。

@detail
### 1. 便利な道具の確認
```python
cards = [11, 10]
print(sum(cards))      # 21     ← リストの合計
print(len(cards))      # 2      ← 枚数
print(11 in cards)     # True   ← 11 が入っているか
cards.remove(11)       # 最初に見つかった 11 を削除 → [10]
cards.append(1)        # 末尾に 1 を追加 → [10, 1]
```

### 2. スコア計算のルールを整理する
| 状況 | 返す値 |
|---|---|
| 2枚で合計 21（エース＋10） | **0**（ナチュラル21の印） |
| 合計 21 超えで、11（エース）がある | 11 を 1 に変えて数え直す |
| それ以外 | そのままの合計 |
「0 を返す」のは、ナチュラル21を普通の 21 と区別するための**目印**です。

### 3. エースを 1 に変える処理
```python
cards = [11, 11, 10]           # 合計 32
while 11 in cards and sum(cards) > 21:
    cards.remove(11)
    cards.append(1)
print(cards, sum(cards))       # [10, 1, 1] 12 ではなく…
```
1回目：11 を 1 に → [11, 10, 1] 合計 22（まだ 21 超え）
2回目：11 を 1 に → [10, 1, 1] 合計 12 → 条件が False で終了

if ではなく **while** にしているのは、エースが2枚以上あるとき「必要なだけ」変えるためです。

> 引数で受け取ったリストを remove すると、**呼び出し元のリストも変わります**（同じリストを指しているため）。気になるなら最初に `cards = list(cards)` でコピーします。

### 4. 勝敗判定は「順番」が命
```python
def compare(user, dealer):
    if user == dealer:
        return "引き分け"
    elif dealer == 0:
        return "負け（相手がナチュラル21）"
    elif user == 0:
        return "勝ち（ナチュラル21）"
    ...
```
例えば user = 25（バースト）、dealer = 25（バースト）のとき、「同点」を先に調べるか「バースト」を先に調べるかで結果が変わります。**問題文の順番どおりに** if / elif を並べ、それぞれ return するのがコツです。

### 5. ゲームのループの考え方
```python
game_over = False
while not game_over:            # game_over が False の間
    user_score = calculate_score(user_cards)
    ...表示...
    if user_score == 0 or user_score > 21:
        game_over = True        # 自動で終わる
    else:
        if input("もう1枚引く？(y/n) ") == "y":
            user_cards.append(deal_card())
        else:
            game_over = True
```
「終わったかどうか」を変数（**フラグ**）で持っておくと、終わる理由が複数あってもすっきり書けます。`not game_over` は「game_over ではない間」。

### 6. ディーラーの番
```python
while dealer_score != 0 and dealer_score < 17:
    dealer_cards.append(deal_card())
    dealer_score = calculate_score(dealer_cards)
```
1枚引くたびに**スコアを計算し直す**のを忘れずに。忘れると条件が変わらず無限ループになります。

> 紙に「開始 → 2枚ずつ配る → 自分の番（くり返し）→ ディーラーの番 → 勝敗」と流れ図を書いてから組み立てると迷いません。

@pitfalls
- **if で 1回だけエースを変える** エース2枚に対応できない → while
- **return し忘れ** compare の各分岐で return がないと None が返る
- **判定の順番が問題文と違う** 同点とバーストが重なるケースなどで結果が変わる
- **スコアの再計算忘れ** カードを引いた後に calculate_score を呼ばないと、古いスコアのまま
- **sum(cards) == 21 だけでナチュラル判定** 3枚で 21 の場合はナチュラルではない → `len(cards) == 2` も条件に

- 11
- 1
E: 2枚で合計21はナチュラル21なので、目印として 0 を返すルールです。

Q: エースを 1 に変える処理を if ではなく while で書く理由は？
- while の方が速いから
* エースが複数あるとき、合計が21以下になるまで何枚でも変えるため
- if では remove が使えないから
- 文法上 while しか使えないから
E: [11, 11, 10] のように、1枚変えてもまだ 21 を超える場合があります。

Q: `game_over = False` のとき `while not game_over:` の意味は？
* game_over が False の間くり返す
- game_over が True の間くり返す
- 1回だけ実行する
- エラーになる
E: not で反転するので「終わっていない間」くり返します。

@steps d11-1
1. 最初に `if len(cards) == 2 and sum(cards) == 21: return 0`
2. 引数のリストを変えないよう `cards = list(cards)` でコピー（おすすめ）
3. `while 11 in cards and sum(cards) > 21:` の中で `cards.remove(11)` と `cards.append(1)`
4. 最後に `return sum(cards)`

@steps d11-2
1. 問題文の 1〜6 の順に、`if` → `elif` … と条件を並べる
2. 1: `user == dealer`、2: `dealer == 0`、3: `user == 0`、4: `user > 21`、5: `dealer > 21`、6: `user > dealer`
3. それぞれの下で、問題文の文字列をそのまま `return`（カッコは全角）
4. どれにも当てはまらなければ `return "負け"`

@steps d11-3
1. `deal_card()` は `return random.choice(cards)`。自分とディーラーに2枚ずつ配る（for _ in range(2) で append）
2. `game_over = False` → `while not game_over:` の中でスコア計算 → 手札・合計とディーラーの1枚目を表示
3. スコアが 0 か 21 超なら `game_over = True`。そうでなければ y/n を聞き、y なら1枚追加、n なら `game_over = True`
4. ループの後、ディーラーは `while dealer_score != 0 and dealer_score < 17:` で引き続ける（毎回スコアを計算し直す）
5. 最後にディーラーの手札と合計、`compare(user_score, dealer_score)` の結果を表示

**スコープ**とは「変数が見える範囲」のことです。

家にたとえると、
- 関数の中で作った変数（**ローカル変数**）は、**その部屋の中だけの持ち物**。部屋の外からは見えません
- ファイルの一番外で作った変数（**グローバル変数**）は、**リビングに置いてある物**。どの部屋からも見えます（ただし、部屋の中から勝手に書き換えるには特別な手続きが必要）

この区別を知らないと「さっき作ったはずの変数がない！」というエラーに悩まされます。

@detail
### 1. 関数の中の変数は外から見えない
```python
def make_potion():
    strength = 2        # ローカル変数（この関数の中だけ）
    print(strength)     # 2  ← 中からは見える

make_potion()
print(strength)         # NameError: name 'strength' is not defined
```
関数が終わると、ローカル変数は**消えます**。

### 2. 外の変数は中から「読める」
```python
level = 3               # グローバル変数

def show():
    print(level)        # 3  ← 読むだけならOK

show()
```

### 3. 中から「書き換える」とエラーになる
```python
score = 0
def add():
    score += 10         # UnboundLocalError!
add()
```
関数の中で `score = ...`（代入）があると、Python は「score はこの関数のローカル変数だ」と判断します。ところがローカルの score にはまだ値がないので、「値が入る前に使った」というエラーになります。

### 4. 直し方① global（あまりおすすめしない）
```python
score = 0
def add():
    global score        # 「外の score を使います」と宣言
    score += 10
add()
print(score)            # 10
```
動きますが、どの関数がいつ書き換えたのか追いにくくなり、大きなプログラムではバグの原因になります。

### 5. 直し方② 引数で受け取り、return で返す（おすすめ）
```python
def add_points(score, points):
    return score + points        # 新しい値を返すだけ

score = 0
score = add_points(score, 10)    # 受け取った値で外の変数を更新
score = add_points(score, 20)
print(f"スコア: {score}")         # スコア: 30
```
関数は「材料を受け取って結果を返す」だけ。外の変数を書き換えるのは呼び出し側、と役割がはっきりします。

### 6. if や for はスコープを作らない
```python
if True:
    message = "やあ"
print(message)          # やあ  ← 使える
```
Python でスコープを作るのは**関数（とクラス）**だけです。

### 7. 定数は大文字で
```python
EASY_TURNS = 10
HARD_TURNS = 5
```
「途中で変えない値」は大文字で書く習慣があります。後から難易度を変えたいとき、ここだけ直せば済みます。

### 8. 1行の if（条件式）
```python
level = "easy"
turns = EASY_TURNS if level == "easy" else HARD_TURNS
```
「条件が True なら左、そうでなければ右」を1行で書けます。

### 9. while … else
```python
while turns > 0:
    ...
    if guess == answer:
        print("正解！")
        break
else:
    print("残念…")       # break されずにループが終わったときだけ実行
```
「最後まで当たらなかった」ときの処理に便利です（普通に if で書いても OK）。

@pitfalls
- **関数の外でローカル変数を使う** → NameError。必要なら return で外に渡す
- **関数の中で外の変数に += する** → UnboundLocalError
- **戻り値を受け取り忘れる** `add_points(score, 10)` だけでは score は変わらない。`score = add_points(score, 10)`
- **数当てで input を int にし忘れる** 文字列と数値を比べられない
- **残り回数の表示タイミング** 問題文どおり「表示してから聞く」

@check
Q: 次のコードを実行すると？
```python
def f():
    x = 5
f()
print(x)
```
- 5 と表示される
- None と表示される
* NameError になる
- 0 と表示される
E: x は f の中だけのローカル変数で、関数の外からは見えません。

Q: global を使わずに、関数で外の変数 count を1増やす書き方は？
- `def up(): count += 1`
* `def up(c): return c + 1` を作り `count = up(count)`
- `def up(): count = count + 1`
- `def up(count): count += 1` を作り `up(count)`
E: 引数で受け取り、新しい値を return して、呼び出し側で代入し直します。最後の選択肢は関数の中の count が変わるだけで、外の count は変わりません。

Q: `t = 10 if mode == "easy" else 5` で mode が "hard" のとき t は？
- 10
* 5
- "hard"
- エラー
E: 条件が False なので else 側の 5 になります。

@steps d12-1
1. エラーの原因は、関数の中で外の score を書き換えようとしていること
2. 関数を `def add_points(score, points):` に変え、中身は `return score + points`
3. 呼び出し側を `score = add_points(score, 10)` のように、戻り値で受け取る形に直す
4. 最後に `スコア: 30` と表示されるか実行して確認

@steps d12-2
1. `EASY_TURNS = 10`、`HARD_TURNS = 5` を定義。`answer = random.randint(1, 100)`
2. 難易度を聞き、`turns = EASY_TURNS if level == "easy" else HARD_TURNS`
3. `check_answer(guess, answer, turns)` は、大きすぎ/小さすぎを表示して `turns - 1` を返す（正解のときは呼ばない）
4. `while turns > 0:` で `残り {turns} 回` → `予想: ` → 正解なら `正解！ 答えは …` を表示して break、違えば `turns = check_answer(...)`
5. 使い切ったら `残念… 答えは …`（while の else、またはループ後に if で）

**デバッグ**とは、プログラムの誤り（**バグ**＝虫）を見つけて直す作業です。プロのプログラマーも、時間の多くをデバッグに使っています。

バグ探しは**探偵の仕事**に似ています。
1. 何が起きたかを正確に確認する（現場検証）
2. エラーメッセージという**証拠**を読む
3. 怪しい場所の値を `print()` で確かめる（聞き込み）
4. 原因を突き止めて直す

勘で書き換えるのではなく、手がかりから原因を絞り込むのが上達のコツです。

@detail
### 1. エラーメッセージは「下から」読む
```text
Traceback (most recent call last):
  File "main.py", line 3, in <module>
    print(age + 1)
TypeError: can only concatenate str (not "int") to str
```
- **一番下の行**：エラーの種類（TypeError）と内容 →「文字列には文字列しかつなげない（int が来た）」
- **その上**：起きた場所（3行目）と、その行のコード
- 原因：age が文字列のまま。`int(input(...))` にし忘れている

### 2. よく出るエラーの意味
| エラー | 意味 | よくある原因 |
|---|---|---|
| SyntaxError | 文法の間違い | コロン・カッコ・クォートの閉じ忘れ |
| IndentationError | 字下げがおかしい | スペースの数がそろっていない |
| NameError | その名前が見つからない | スペルミス、定義前に使用、クォート忘れ |
| TypeError | 型の組み合わせがおかしい | 文字列と数値の + |
| ValueError | 値が変換できない | `int("abc")` |
| IndexError | 番号が範囲外 | 長さ3のリストに [3] |
| KeyError | 辞書にそのキーがない | キーのスペルミス |

### 3. エラーが出ない「論理バグ」が一番やっかい
エラーは出ないのに結果がおかしい場合は、**値を表示して確かめます**。
```python
def count_words(text):
    for word in text.split():
        counts = {}                 # ← 怪しい？
        counts[word] = counts.get(word, 0) + 1
        print("途中:", word, counts)    # デバッグ用の print
    return counts
```
▶ 実行結果（count_words("a b a")）
```
途中: a {'a': 1}
途中: b {'b': 1}       ← a が消えている！
途中: a {'a': 1}
```
毎回 counts が空に戻っていることが一目で分かります。→ `counts = {}` をループの**前**に移せば解決。直したらデバッグ用の print は消しましょう。

### 4. コンピューターになりきって追う（トレース）
```python
dice = ["⚀", "⚁", "⚂", "⚃", "⚄", "⚅"]
n = random.randint(1, 6)
print(dice[n])
```
- dice のインデックスは 0〜5
- n は 1〜6 のどれか
- n が 6 のとき dice[6] → **範囲外**！（ときどきしか起きないのは、6 が出たときだけだから）

「ときどき起きる」バグは、**特定の値のときだけ**起きていることが多いです。端の値（最小・最大）を疑いましょう。

### 5. 境界の値を確かめる
```python
if year > 1980 and year < 1994:     # 1980 と 1994 ちょうどが含まれない！
```
「1980〜1994」は 1980 と 1994 を**含む**ので `>=` と `<=`。範囲の問題では**境界の値をわざと入力**してテストするのが鉄則です。

### 6. インデントのずれ
```python
for word in words:
    counts[word] = ...
    return counts        # ← ループの中にあるので、1回目で関数が終わる
```
return をループの外（for と同じ深さ）に出す必要があります。インデント1段の違いで動きがまったく変わります。

### 7. AI に聞くときのコツ
エラーメッセージ**全文**＋**コード**＋**期待した動き**＋**実際の動き**をセットで伝えると、的確な答えが返ってきます。このアプリの「AI 先生」の「エラーを解説」ボタンも、自動でこれらを送っています。

@pitfalls
- **エラーメッセージを読まずに書き換える** まず一番下の行と行番号を見る
- **直したつもりで確認しない** 直したら同じ入力でもう一度実行
- **一度に何か所も変える** 何が効いたか分からなくなる。1か所ずつ
- **デバッグ用の print を消し忘れる** 採点で表示が余分になることがある

@check
Q: `IndexError: list index out of range` の意味は？
- リストが空
* リストにない番号（範囲外）を指定した
- リストに数値以外が入っている
- リストのスペルミス
E: 長さ6のリストに [6] のように、存在しない位置を指定したときのエラーです。

Q: 「1980〜1994年（両端を含む）」の正しい条件は？
- `1980 < year < 1994`
* `1980 <= year <= 1994`
- `year > 1980 or year < 1994`
- `year >= 1980 and year < 1994`
E: 両端を含むので <= を使います。

Q: 関数の中のループに return を書いたら、結果が1件分しか返らない。原因として最も考えられるのは？
- return を2回書いていない
* return がループの中にあり、1回目で関数が終わっている
- ループの条件が間違っている
- 辞書が使えない
E: return は関数をその場で終わらせます。ループの外（インデントを戻す）に書きます。

@steps d13-1
1. dice の要素は6つ → インデックスは 0〜5
2. `random.randint(1, 6)` は 6 も出る → dice[6] で範囲外
3. 直し方は2通り：`randint(0, 5)` にする、または `dice[n - 1]` にする（どちらか1つ）

@steps d13-2
1. 1994 を入力したときにどの条件にも当てはまらない理由を考える
2. 条件が `>`・`<` になっていて、境界の 1980 や 1994 が含まれていない
3. `>=` と `<=` に直す（Z世代の 1995〜2012 も同様に確認）

@steps d13-3
1. バグ①：`counts = {}` がループの中にあり、毎回空に戻る → ループの前へ移動
2. バグ②：`return counts` がループの中にあり、1回目で関数が終わる → インデントを戻してループの外へ
3. 直したら `count_words("a b a c a")` を実行して `{'a': 3, 'b': 1, 'c': 1}` になるか確認

「富士山と北岳、どっちが高い？」と2択で当てていくゲームを作ります。

今日のテーマは **データと処理を分けて整理する** ことです。山のデータは「辞書のリスト」にまとめ、
- データを見やすい文字列にする関数
- 答えが合っているか判定する関数

を部品として作ってから、ゲームの流れ（ループ）を組み立てます。データを「都市の人口」に入れ替えれば、同じ部品で別のゲームにもなります。

@detail
### 1. データの形（辞書のリスト）
```python
data = [
    {"name": "富士山", "pref": "山梨・静岡", "height": 3776},
    {"name": "北岳", "pref": "山梨", "height": 3193},
    {"name": "奥穂高岳", "pref": "長野・岐阜", "height": 3190},
]
```
- リストの1つ1つが「1つの山」を表す辞書
- 山の名前は `data[0]["name"]`、高さは `data[0]["height"]`
- `random.choice(data)` で山を1つ（辞書まるごと）選べる

### 2. 部品①：表示用の文字列を作る
```python
def format_item(item):
    return f"{item['name']}（{item['pref']}）"

print(format_item(data[0]))     # 富士山（山梨・静岡）
```
> f文字列の外側を `" "` で囲んでいるので、中のキーは `' '`（シングルクォート）にします。同じ `"` を使うと文字列がそこで終わってしまいます。

### 3. 部品②：答えを判定する
```python
def check_answer(guess, a_height, b_height):
    if a_height > b_height:
        return guess == "a"      # A が高いなら、"a" と答えていれば正解
    else:
        return guess == "b"
```
`guess == "a"` は True か False になる式なので、そのまま return できます。
```python
print(check_answer("a", 3776, 3193))    # True
print(check_answer("b", 3776, 3193))    # False
```

### 4. A と B が同じにならないように
```python
a = random.choice(data)
b = random.choice(data)
while b == a:                # 同じ山を引いたら
    b = random.choice(data)  # 引き直す
```

### 5. ゲームのループ
```python
score = 0
a = random.choice(data)
while True:
    b = random.choice(data)
    while b == a:
        b = random.choice(data)
    print(f"A: {format_item(a)}")
    print(f"B: {format_item(b)}")
    guess = input("どっちが高い？(a/b) ").lower()
    if check_answer(guess, a["height"], b["height"]):
        score += 1
        print(f"正解！ スコア: {score}")
        a = b                       # ← B が次の問題の A になる
    else:
        print(f"残念！ 最終スコア: {score}")
        break
```
`a = b` で「勝ち残った山」が次の比較に使われます。部品の関数があるおかげで、ループの中は「流れ」だけを書けばよく、読みやすくなっています。

### 2. 材料が足りるか調べる
```python
def is_enough(order_ingredients, resources):
    for item, amount in order_ingredients.items():
        if amount > resources[item]:
            print(f"申し訳ありません、{item} が足りません")
            return False          # 1つでも足りなければ、その場で終了
    return True                   # 全部見て問題なければ True
```
- 必要な材料を1つずつ見て、在庫と比べる
- **足りないものが見つかった時点で False を返して終了**
- ループを最後まで抜けたら「全部足りた」ので True

`return True` を**ループの中に書かない**のがポイントです（1つ目の材料だけで判断してしまうため）。
