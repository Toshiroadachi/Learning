**オブジェクト指向（OOP）**は、プログラムを「**モノ（オブジェクト）**の集まり」として考える方法です。

スマホにたとえると、スマホには
- **データ（属性）**：電池残量、音量、画面の明るさ
- **できること（メソッド）**：電話をかける、写真を撮る、音量を上げる

がセットで入っています。電池残量を知りたければ `phone.battery`、写真を撮りたければ `phone.take_photo()` ── データと機能が1つにまとまっているので、使う人は中の仕組みを知らなくても使えます。

実はあなたはもう、オブジェクトを使っています。`"abc".upper()` の `"abc"` も、`fruits.append()` の `fruits` もオブジェクトです。

@detail
### 1. 4つの言葉
| 言葉 | たとえ | Python での例 |
|---|---|---|
| **クラス** | 設計図・金型 | `date`、`str`、`list` |
| **オブジェクト（インスタンス）** | 設計図から作った実物 | `date(2026, 12, 25)` |
| **属性** | 実物が持っているデータ | `d.year` |
| **メソッド** | 実物ができること | `d.weekday()` |
属性は `.名前`（カッコなし）、メソッドは `.名前()`（カッコあり＝実行する）。

### 2. クラスからオブジェクトを作る
```python
from datetime import date        # datetime モジュールから date クラスだけ持ってくる

d = date(2026, 12, 25)           # クラス名(…) でオブジェクトを作る
print(d.year)                    # 2026   ← 属性
print(d.month)                   # 12
print(d.weekday())               # 4      ← メソッド（0=月曜 … 4=金曜）
print(d.isoformat())             # 2026-12-25
```
`date(2026, 12, 25)` と `date(2027, 1, 1)` は同じ設計図から作った**別々のオブジェクト**で、それぞれ自分の year や month を持っています。

### 3. オブジェクト同士の計算
```python
from datetime import date
today = date(2026, 11, 23)
xmas = date(2026, 12, 25)
diff = xmas - today              # 日付の引き算 → timedelta という別のオブジェクト
print(diff.days)                 # 32  ← timedelta の属性
print(xmas < today)              # False ← 日付の比較もできる
```

### 4. Counter — 数えるのが得意なクラス
```python
from collections import Counter
c = Counter("banana")
print(c)                  # Counter({'a': 3, 'n': 2, 'b': 1})
print(c["a"])             # 3
print(c.most_common(1))   # [('a', 3)]  ← 多い順に1つ（リストの中にタプル）
```
`most_common(1)` は「リストの中に (文字, 回数) の組が1つ」という形です。取り出すには：
```python
ch, n = c.most_common(1)[0]    # [0] で組を取り出し、2つの変数に分ける
print(f"{ch}: {n}")            # a: 3
```

### 5. str も list もクラス
```python
print(type("abc"))       # <class 'str'>
print(type([1, 2]))      # <class 'list'>
print(dir("abc"))        # 使えるメソッドの一覧（upper, split, replace …）
```
`.upper()` や `.append()` は、それぞれのクラスに用意されたメソッドだったのです。

### 6. ドキュメントを読む力
知らないクラスは公式ドキュメント（docs.python.org/ja）で「何を渡して作るか」「どんな属性・メソッドがあるか」を調べます。全部覚える必要はなく、**調べて使えればOK**です。

@pitfalls
- **メソッドの () を忘れる** `d.weekday` は関数そのもの。結果が欲しいなら `d.weekday()`
- **属性に () を付ける** `d.year()` → TypeError（year は値なので呼べない）
- **import の形** `import datetime` なら `datetime.date(…)`。`from datetime import date` なら `date(…)`
- **most_common の形** `[('a', 3)]` はリスト。`[0]` で組を取り出してから使う
- **過ぎた誕生日** 今年の日付が今日より前なら、来年の日付で計算し直す

- エラー（month() と書く必要がある）
E: month は属性なので、カッコなしで値 5 が取れます。

* クラスは設計図、オブジェクトはそこから作った実物
- クラスは実物、オブジェクトは設計図
- 同じ意味の言葉
- クラスは関数のこと
E: 1つのクラス（設計図）から、いくつでもオブジェクト（実物）を作れます。

- "a"
- 2

E: most_common(1) は [("a", 2)]。その [0] で組 ("a", 2) になります。

Day 16 ではできあがったクラスを使いました。今日は**自分でクラス（設計図）を作ります**。

たとえば「ユーザー」の設計図を作れば、たろうさん・はなこさん…と何人でも作れて、それぞれが自分の名前やフォロワー数を持ちます。

クイズアプリでは、
- **Question**（問題1問分：問題文と答え）
- **QuizBrain**（クイズの進行役：何問目か・スコア・出題・採点）

という2つの設計図を作り、役割を分担させます。

@detail
### 1. いちばん小さなクラス
```python
class Question:
    def __init__(self, text, answer):
        self.text = text
        self.answer = answer

q = Question("富士山は日本一高い", "True")
print(q.text)       # 富士山は日本一高い
print(q.answer)     # True
```
- `class クラス名:` で設計図の始まり。クラス名は単語の頭を大文字に（Question、QuizBrain）
- `__init__`（イニット）は、**オブジェクトを作るときに自動で呼ばれる準備の関数**
- `Question("…", "True")` と書くと、`__init__(self, "…", "True")` が実行される

### 2. self とは何か
`self` は「**今つくっている（使っている）そのオブジェクト自身**」です。
```python
self.text = text
```
は「このオブジェクトの text という属性に、引数 text の値を入れる」という意味。`self.` を付けた変数は**オブジェクトに保存され**、関数が終わっても消えません（付けない変数は関数のローカル変数で、終わると消える）。

```python
q1 = Question("A", "True")
q2 = Question("B", "False")
print(q1.text, q2.text)     # A B  ← それぞれ自分の text を持っている
```

### 3. メソッドを作る
```python
class User:
    def __init__(self, name):
        self.name = name
        self.followers = 0           # 最初は 0（引数で受け取らない属性）

    def follow(self, other):          # メソッドの最初の引数は必ず self
        other.followers += 1

a = User("たろう")
b = User("はなこ")
a.follow(b)                           # 呼ぶときは self を書かない
print(b.followers)                    # 1
```
`a.follow(b)` と呼ぶと、self に a、other に b が入ります。

### 4. QuizBrain — 状態を持つクラス
```python
class QuizBrain:
    def __init__(self, questions):
        self.number = 0              # 今何問目か
        self.score = 0               # 正解数
        self.questions = questions   # Question のリスト

    def still_has_questions(self):
        return self.number < len(self.questions)

    def next_question(self):
        q = self.questions[self.number]
        self.number += 1
        ans = input(f"Q{self.number}. {q.text} (True/False): ")
        self.check_answer(ans, q.answer)     # 同じクラスのメソッドも self. で呼ぶ
```
`self.number` を1つずつ増やしながら、リストから次の問題を取り出します。number を先に増やしているので、表示は Q1, Q2 … になります。

### 5. 組み立て
```python
questions = [Question("…", "True"), Question("…", "False")]
quiz = QuizBrain(questions)
while quiz.still_has_questions():
    quiz.next_question()
print(f"終了！ 最終スコア: {quiz.score}/{quiz.number}")
```
メインの流れは「問題がある間、次の問題を出す」だけ。細かい処理はクラスの中に隠れているので、とても読みやすくなります。

@pitfalls
- **self を書き忘れる** `def follow(other):` → 呼び出しで引数の数が合わずエラー。メソッドの最初は必ず self
- **self. を付け忘れる** `score = 0` では属性にならず、他のメソッドから見えない
- **__init__ のつづり** アンダースコアは前後に2つずつ（`__init__`）
- **呼び出しで self を渡す** `a.follow(a, b)` は誤り。self は自動で入る
- **比べる答えの大文字小文字** "true" と "True" は別物。`.lower()` でそろえて比べると親切

@check
Q: `class Dog:` の `__init__` はいつ実行される？
- import したとき
* `Dog(…)` でオブジェクトを作ったとき
- メソッドを呼んだとき毎回
- プログラムの最後
E: オブジェクトを作る瞬間に自動で呼ばれ、属性の準備をします。

Q: メソッドの中で `self.count = 0` と `count = 0` の違いは？
* self.count はオブジェクトに保存され他のメソッドからも使える。count はその関数の中だけ
- 違いはない
- count の方が長く残る
- self.count は定数になる
E: self. を付けるとオブジェクトの属性になります。

Q: `a = User("たろう")` のあと `a.follow(b)` を呼ぶとき、follow の self に入るのは？
* a
- b
- User
- "たろう"
E: ドットの前のオブジェクトが self に入ります。

@steps d17-1
1. `Question` の `__init__(self, text, answer)` で `self.text`・`self.answer` に保存
2. `QuizBrain` の `__init__` で `self.number = 0`・`self.score = 0`・`self.questions = questions`
3. `still_has_questions` は `return self.number < len(self.questions)`
4. `next_question`：問題を取り出し → number を1増やす → `Q{番号}. {問題文} (True/False): ` で input → `self.check_answer(ans, q.answer)`
5. `check_answer`：正解なら score を増やして `正解！`、違えば `不正解… 答えは {correct}`。続けて `現在のスコア: {score}/{number}`。最後にメイン部分で `終了！ 最終スコア: …`

**turtle（タートル）**は、画面の上にいる「カメ」にペンを持たせて、命令で動かして絵を描くモジュールです。

「100歩進んで、右に90度回る」を4回くり返すと正方形 ── このように**ループと図形の関係**が目で見て分かるので、for の練習にぴったりです。今日はもう1つ、**ドキュメントを読んで使い方を調べる**練習もします。

@detail
### 1. 最初の一筆
```python
from turtle import Turtle, Screen
t = Turtle()            # カメ（Turtle クラスのオブジェクト）を1匹作る
t.forward(100)          # 前へ 100 進む（線が引かれる）
t.right(90)             # 右へ 90 度回る
t.forward(100)
```
カメは最初、画面の中心 (0, 0) で**右（東）**を向いています。

### 2. 正方形 → 正多角形
```python
for _ in range(4):
    t.forward(100)
    t.right(90)
```
正 n 角形は、**1周 360 度を n 回に分けて回る**と描けます。
| 図形 | n | 1回に回る角度 |
|---|---|---|
| 正三角形 | 3 | 360 / 3 = 120 |
| 正方形 | 4 | 90 |
| 正六角形 | 6 | 60 |
```python
n = 6
for _ in range(n):
    t.forward(80)
    t.right(360 / n)
```

### 3. よく使う命令
| 命令 | 動き |
|---|---|
| `forward(距離)` / `back(距離)` | 前へ / 後ろへ |
| `left(角度)` / `right(角度)` | 左へ / 右へ回る |
| `penup()` / `pendown()` | ペンを上げる（線を引かずに移動）/ 下ろす |
| `goto(x, y)` | 座標へ移動 |
| `setheading(角度)` / `heading()` | 向きを設定 / 今の向き（0=右, 90=上） |
| `circle(半径)` | 円を描く |
| `color("red")` / `pensize(太さ)` | 色 / 線の太さ |
| `speed("fastest")` | 描く速さ |
座標は中心が (0, 0)、右が x のプラス、上が y のプラス（数学のグラフと同じ）。

### 4. 点線（penup / pendown）
```python
for _ in range(15):
    t.forward(10)     # 描く
    t.penup()
    t.forward(10)     # 描かずに進む（すき間）
    t.pendown()
```

### 5. タプルと RGB の色
```python
color = (30, 144, 255)       # 丸カッコ = タプル（中身を変更できないリスト）
```
色は赤・緑・青の強さ（0〜255）の組で表せます。
```python
import random
def random_color():
    return (random.randint(0, 255), random.randint(0, 255), random.randint(0, 255))

screen = Screen()
screen.colormode(255)        # 0〜255 で色を指定するモードに
t.pencolor(random_color())
```

### 6. スピログラフ（円を回しながら重ねる）
```python
for _ in range(36):
    t.circle(100)
    t.setheading(t.heading() + 10)    # 向きを 10 度ずらす
```
10度 × 36回 = 360度で、ちょうど1周分の円が重なります。

### 7. import の3つの書き方
```python
import turtle              # → turtle.Turtle()（毎回モジュール名を書く）
from turtle import Turtle  # → Turtle()（名前だけで使える）
import turtle as tt        # → tt.Turtle()（短い別名）
```

> このアプリでは、実行が終わった後に描画がアニメーションで表示されます。

@pitfalls
- **回る角度の計算** 正 n 角形は外角 360/n。内角（例：正三角形の 60）を使うと閉じない
- **range の範囲** 3〜10角形は `range(3, 11)`
- **colormode を忘れる** (255, 0, 0) を渡すとエラー。`screen.colormode(255)` が先
- **penup したまま** 点線で pendown を忘れると、以降の線が描かれない
- **大文字小文字** `Turtle` `Screen` はクラスなので大文字始まり

同じ設計図（クラス）から作ったオブジェクトは、**それぞれ別々の状態（位置・色など）**を持っています。

同じ型で焼いたたい焼きでも、1匹目はあんこ、2匹目はクリーム、と中身が違っていいのと同じです。今日は6匹のカメを作って競争させ、「同じクラスから作った複数のオブジェクトを、リストでまとめて動かす」練習をします。

@detail
### 1. 2匹のカメは別人
```python
from turtle import Turtle
a = Turtle()
b = Turtle()
a.color("red")       # a だけ赤くなる
b.goto(0, 100)       # b だけ移動する
print(a.position(), b.position())    # (0.00,0.00) (0.00,100.00)
```
a を変えても b は変わりません。それぞれが自分の属性（色・位置）を持っています。

### 2. たくさん作ってリストに入れる
```python
colors = ["red", "orange", "gold", "green", "blue", "purple"]
racers = []
for i, c in enumerate(colors):          # i = 0〜5、c = 色
    t = Turtle(shape="turtle")
    t.color(c)
    t.penup()
    t.goto(-230, -100 + i * 40)         # y = -100, -60, -20, 20, 60, 100
    racers.append(t)
```
`enumerate` で番号 i も一緒に取り出し、i を使って縦の位置をずらしています。ループが終わると racers に6匹のカメが入っています。

### 3. リストのカメを全員動かす
```python
import random
for t in racers:
    t.forward(random.randint(0, 10))
```
1行で全員を動かせるのが、リストでまとめる良さです。

### 4. レースのループ
```python
is_on = True
winner = None
while is_on:
    for t in racers:
        t.forward(random.randint(0, 10))
        if t.xcor() > 230:          # xcor() は今の x 座標
            is_on = False
            winner = t.pencolor()   # そのカメの色
            break                   # for を抜ける（他のカメはもう動かさない）
print(f"優勝は {winner}！")
```
- `break` が抜けるのは**一番内側のループ（for）だけ**
- そのあと while の条件 `is_on` が False なので、while も終わります（フラグの出番）

### 5. 関数を「渡す」（PC で試す内容）
```python
def move_forward():
    t.forward(10)

screen.onkey(move_forward, "Up")    # ↑キーが押されたら move_forward を呼んでね
screen.listen()
```
`move_forward`（カッコなし）は**関数そのもの**、`move_forward()` は**今すぐ実行した結果**です。onkey には「後で呼んでほしい関数」を渡すので、カッコを付けません。

> キー操作のイベントはこのアプリでは動きません。PC に Python を入れて試してみましょう。

@pitfalls
- **1匹のカメを使い回す** ループの中で毎回 `Turtle()` を作らないと、6匹にならない
- **break で while まで抜けると思う** break は内側の for だけ。フラグ（is_on）で while も止める
- **予想の比較** 入力した色と `winner` を比べる。大文字小文字や空白に注意
- **onkey に () 付きで渡す** 渡した瞬間に1回実行されてしまう

@steps d19-1

有名な「ヘビゲーム」を2日に分けて作ります。今日はヘビの**体の動き**だけを作ります。

ヘビの体は「節（ふし）」の行列です。前に進むとき、
- 頭が1マス進む
- 2番目の節は、さっきまで頭がいた場所へ
- 3番目の節は、さっきまで2番目がいた場所へ…

と、**後ろの節が前の節を追いかける**ように動きます。電車ごっこで、前の人がいた場所に次の人が進むイメージです。

今回は画面に描くことと切り離して、**座標（数字）だけで動くヘビ**をクラスで作ります。数字だけなので、動きが正しいか確かめやすくなります。

@detail
### 1. ヘビを座標のリストで表す
```python
segments = [(0, 0), (-20, 0), (-40, 0)]
#            頭        2番目      しっぽ
```
1節の大きさを 20 として、頭が (0, 0)、そこから左へ 20 ずつ体が続いています（右向きに進んでいる状態）。

### 2. 方向を数字で表す
```python
MOVE = 20
DIRS = {"up": (0, 1), "down": (0, -1), "left": (-1, 0), "right": (1, 0)}
```
"right" なら x を +1 方向、y はそのまま。これに MOVE(20) を掛けると、1回の移動量になります。
```python
dx, dy = DIRS["right"]      # dx = 1, dy = 0
x, y = (0, 0)
print((x + dx * MOVE, y + dy * MOVE))    # (20, 0)
```

### 3. 体を動かす（後ろから順に）
```python
for i in range(len(segments) - 1, 0, -1):    # i = 2, 1（後ろから）
    segments[i] = segments[i - 1]            # 1つ前の節の位置へ
```
`range(2, 0, -1)` は 2, 1（0 は含まない、-1 ずつ減る）。

| 処理 | segments |
|---|---|
| 最初 | [(0,0), (-20,0), (-40,0)] |
| i=2：しっぽ ← 2番目 | [(0,0), (-20,0), (-20,0)] |
| i=1：2番目 ← 頭 | [(0,0), (0,0), (-20,0)] |
| 頭を右へ 20 | [(20,0), (0,0), (-20,0)] |

**前から**順に動かすと、2番目が頭の位置になった後、3番目もその（新しい）位置をコピーしてしまい、体が縮んでしまいます。だから**後ろから**。

### 4. クラスにまとめる
```python
class Snake:
    def __init__(self):
        self.segments = [(0, 0), (-20, 0), (-40, 0)]
        self.direction = "right"

    def head(self):
        return self.segments[0]

    def move(self):
        for i in range(len(self.segments) - 1, 0, -1):
            self.segments[i] = self.segments[i - 1]
        dx, dy = DIRS[self.direction]
        x, y = self.segments[0]
        self.segments[0] = (x + dx * MOVE, y + dy * MOVE)
```

### 5. 逆向きには曲がれない
```python
OPPOSITE = {"up": "down", "down": "up", "left": "right", "right": "left"}

def turn(self, new_dir):
    if new_dir != OPPOSITE[self.direction]:
        self.direction = new_dir
```
右に進んでいるのに急に左へ行くと、自分の体にぶつかってしまうので無視します。

### 6. 描くのは最後に
```python
pen = Turtle()
pen.shape("square")
pen.penup()
for i, (x, y) in enumerate(snake.segments):
    pen.goto(x, y)
    pen.color("lime" if i == 0 else "white")   # 頭だけ別の色
    pen.stamp()                                # その場に形をはんこのように押す
```
「計算（Snake クラス）」と「表示（draw 関数）」を分けておくと、表示を変えても計算は変えずに済みます。

@pitfalls
- **前から順に動かす** 体が重なって縮む → 後ろから
- **タプルの中身を直接変える** `segments[0][0] += 20` はエラー（タプルは変更不可）。新しいタプルを作って入れ直す
- **range の終わり** `range(len - 1, 0, -1)` は 0 を含まない（頭は別に動かすため、これで正しい）
- **turn で逆方向を許してしまう** 逆方向の対応表（辞書）で判定
- **操作列の文字と方向名** "R"→"right" のように変換する辞書を用意する

@check

- 0, 1, 2, 3
- 何も作らない

ヘビゲームを完成させるための3つの道具を学びます。

- **継承**：昨日作った Snake の機能を**そのまま引き継いで**、「伸びる」「ぶつかる」機能を追加した新しいクラスを作る（スマホの新機種が、前の機種の機能を受け継いで新機能を足すイメージ）
- **スライス**：リストの「一部分」を切り出す（パンを好きな厚さで切り出すイメージ）
- **当たり判定**：頭が壁や自分の体に重なったかを調べる

@detail
### 1. 継承の基本
```python
class Animal:
    def __init__(self):
        self.eyes = 2
    def breathe(self):
        print("吸って、吐いて")

class Fish(Animal):              # ( ) の中に親クラス → Animal を継承
    def swim(self):
        print("すいすい")

f = Fish()
f.breathe()     # 吸って、吐いて   ← 親のメソッドがそのまま使える
f.swim()        # すいすい         ← 子で追加したメソッド
print(f.eyes)   # 2               ← 親の __init__ で作った属性もある
```

### 2. 上書き（オーバーライド）と super()
```python
class Fish(Animal):
    def __init__(self):
        super().__init__()       # 親の __init__ を実行（eyes = 2 を作る）
        self.fins = 4            # 子だけの属性を追加
    def breathe(self):           # 同じ名前で書くと上書き
        super().breathe()        # 親の breathe も呼ぶ
        print("水中で")
```
`super()` は「親クラス」のこと。子で `__init__` を書くときは、親の準備を忘れないよう `super().__init__()` を呼びます。

### 3. スライス `[始め:終わり]`
```python
nums = [10, 11, 12, 13, 14]
print(nums[1:4])    # [11, 12, 13]   ← 1番から、4番の手前まで
print(nums[:2])     # [10, 11]       ← 最初から2番の手前まで
print(nums[1:])     # [11, 12, 13, 14] ← 1番から最後まで（＝先頭以外）
print(nums[-2:])    # [13, 14]       ← 最後の2つ
print(nums[::-1])   # [14, 13, 12, 11, 10] ← 逆順
```
range と同じく「終わりの番号は含まない」ルールです。`[1:]` は「頭以外の体」を取り出すのにぴったりです。

### 4. ヘビを伸ばす
```python
def extend(self):
    self.segments.append(self.segments[-1])    # しっぽと同じ位置に1節追加
```
しっぽに重ねて追加しておくと、次の move() で体が1つずつ前へずれるので、重なっていた節が自然に「伸びた分」になります。

### 5. 当たり判定
```python
def hit_wall(self):
    x, y = self.head()
    return abs(x) > 280 or abs(y) > 280     # abs = 絶対値（マイナスを外す）

def hit_self(self):
    return self.head() in self.segments[1:] # 頭が「頭以外の体」のどこかと同じ位置か
```
- `abs(-300)` は 300。左右・上下の両方の壁を1つの式で調べられる
- `in` でリストの中に同じ座標があるか調べる。`[1:]` にしないと、頭は必ず自分自身（segments[0]）と一致してしまう

### 6. 完成形のイメージ
```python
class GameSnake(Snake):
    def extend(self): ...
    def hit_wall(self): ...
    def hit_self(self): ...

s = GameSnake()           # Snake の move や turn もそのまま使える
s.move()
if s.hit_wall() or s.hit_self():
    print("GAME OVER")
```

@pitfalls
- **親の __init__ を呼び忘れる** 子で `__init__` を書いたのに `super().__init__()` がないと、segments などの属性がない
- **hit_self で [1:] を付け忘れる** 頭は自分自身と一致するので、常に True になる
- **スライスの終わり** `[1:3]` は 1 と 2 だけ
- **abs を忘れる** `x > 280` だけでは左（マイナス側）の壁を判定できない
- **継承の書き方** `class GameSnake(Snake):`。カッコの中は親クラスの名前

- [6, 7, 8]
- [7, 8]
E: 1番から3番の手前（1と2）までです。

Q: `class B(A):` と書いたとき、B のオブジェクトは？
* A のメソッドも使える
- A のメソッドは使えない

卓球ゲーム「ポン」の**ボールの物理**を作ります。

ボールの動きは「**毎回、少しずつ位置をずらす**」だけで表現できます。パラパラ漫画と同じで、1コマごとに x を 10、y を 10 動かすと、斜めに動いて見えます。

壁に当たったら跳ね返る ── これも「進む向き（符号）を反対にする」だけ。上下の壁なら縦の向き、パドル（ラケット）なら横の向きを反転させます。

@detail
### 1. 位置と速度
```python
class Ball:
    def __init__(self):
        self.x, self.y = 0, 0        # 位置
        self.dx, self.dy = 10, 10    # 1回に動く量（速度）
    def move(self):
        self.x += self.dx
        self.y += self.dy

b = Ball()
b.move(); b.move()
print(b.x, b.y)      # 20 20  ← 右上へ進んでいる
```
`self.x, self.y = 0, 0` は2つの属性にまとめて代入する書き方です。

### 2. 跳ね返り＝符号を反転
```python
def bounce_y(self):          # 上下の壁
    self.dy *= -1            # 10 → -10（上向き → 下向き）
def bounce_x(self):          # パドル
    self.dx *= -1.1          # 向きを反転して、少し速く（1.1倍）
```
`*= -1` は「-1 を掛けて入れ直す」＝向きだけ反対になり、速さは同じです。

| 当たったもの | 反転するもの | 理由 |
|---|---|---|
| 上・下の壁 | dy | 縦方向だけ跳ね返る |
| 左右のパドル | dx | 横方向だけ跳ね返る |

### 3. パドルとの当たり判定
パドルは縦長の板（中心が (x, y)、高さ 100）。ボールが当たっているのは、
- 横方向：ボールの x がパドルの x に十分近い（差が 20 未満）
- 縦方向：ボールの y がパドルの中心から ±50 以内
```python
class Paddle:
    def __init__(self, x):
        self.x = x
        self.y = 0
    def up(self):
        self.y += 20
    def down(self):
        self.y -= 20
    def hits(self, ball):
        return abs(ball.x - self.x) < 20 and abs(ball.y - self.y) < 50
```
`abs(a - b)` は「a と b の距離（差の大きさ）」。どちら側にずれていても同じ式で判定できます。

### 4. 得点したらボールを中央へ
```python
def reset(self):
    self.x, self.y = 0, 0
    self.dx = -10 if self.dx > 0 else 10    # 向きは反対に、速さは初期値に
    self.dy = 10
```
得点された側へ向けてサーブし直すイメージです。

### 5. 1コマ分の処理をまとめる
```python
def step(ball, left, right):
    ball.move()
    if abs(ball.y) > 280:
        ball.bounce_y()
    if left.hits(ball) or right.hits(ball):
        ball.bounce_x()
    if ball.x > 380:          # 右端を越えた → 左の得点
        ball.reset()
        return "L"
    if ball.x < -380:         # 左端を越えた → 右の得点
        ball.reset()
        return "R"
    return None
```
PC 版のゲームでは、この step を `while` ループで何度も呼び、そのたびに `screen.update()` で画面を描き直し、`time.sleep(0.05)` で少し待つことでアニメーションになります。

@pitfalls
- **反転する向きの取り違え** 上下の壁で dx を反転すると、壁をすり抜けて横に跳ねる
- **reset で速さを戻し忘れる** 1.1倍が積み重なって速くなり続ける
- **得点の向き** 右端を越えたら「左の得点」。問題文どおり "L" / "R"
- **reset の後に return を忘れる** None ではなく得点した側を返す
- **abs を使わない判定** パドルの上側・下側の片方しか判定できない
