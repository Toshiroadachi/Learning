@@lesson pq1
@image
パワークエリは **「データ整形の作業を録画して、何度でも再生できるレコーダー」** です。

毎月届く売上 CSV を開いて、①いらない列を消す ②日付をそろえる ③商品名を付ける…という作業を、手で毎月くり返していませんか？ パワークエリでは、1回目に操作した手順が **「適用したステップ」** として記録されます。翌月は元データを差し替えて **「更新」ボタンを押すだけ** で、同じ手順が自動でもう一度実行されます。

Excel の関数やマクロと違い、**元のデータは一切書き換えません**。元データ → 手順 → 結果の表、という流れが常に保たれるので、やり直しも簡単です。

@detail
### 1. Excel の普通の作業との違い
| | 手作業（Excel） | パワークエリ |
|---|---|---|
| 元データ | 直接書き換える | **書き換えない**（読み込むだけ） |
| 手順 | 頭の中・メモ | 「適用したステップ」に自動で記録 |
| 来月 | また最初から手作業 | **更新ボタン1つ** |
| 間違えたら | 元に戻すのが大変 | そのステップを消すだけ |

### 2. 画面の見方（このアプリの演習画面も同じ配置）
- **上（リボン）**：ホーム／変換／列の追加 のタブ。操作ボタンが並ぶ
- **数式バー（fx）**：今選んでいるステップの中身（M 言語の式）
- **中央（プレビュー）**：そのステップ時点のデータ。上位の行だけが表示される
- **下（適用したステップ）**：操作の記録。**クリックするとその時点のデータに戻って見られる**（ステップは消えない）

### 3. 列見出しのアイコン＝データ型
| アイコン | 型 | 例 |
|---|---|---|
| ABC | テキスト | 顧客名、商品ID |
| 123 | 整数 | 数量、注文ID |
| 1.2 | 10進数 | 単価（小数あり） |
| 📅 | 日付 | 2026/04/01 |
| ABC123 | **任意**（型が決まっていない） | 読み込んだ直後 |

読み込んだ直後の列は多くが「任意」です。このままだと日付で並べ替えたり、数値で合計したりが正しくできないことがあります。そこで **最初の作業は「型を正しく設定する」** になります。

### 4. 型を変えると何が起きる？（ビフォー・アフター）
変更前（任意）：
| 日付 | 数量 |
|---|---|
| 2026/04/01 | 3 |
| 2026/04/01 | 10 |

日付列を「日付」、数量列を「整数」に変更すると、見た目は似ていても中身が **「文字」から「日付」「数」** に変わります。アイコンが 📅 と 123 になり、日付フィルターや合計が使えるようになります。

### 5. 裏で書かれている M 言語
「型の変更」を押すと、数式バーにこんな式が記録されます。
```powerquery
= Table.TransformColumnTypes(ソース,{{"日付", type date}, {"数量", Int64.Type}})
```
読み方：「**ソース**（1つ前のステップ）の表について、日付 列を日付型に、数量 列を整数型に変える」。最初は読めなくて大丈夫です。操作するたびに数式バーを眺めていると、だんだん読めるようになります。

> 演習の操作方法：列見出しを**タップ**すると選択されメニューが開きます。もう一度タップすると選択解除。複数の列を選んでから「型の変更」をすると、まとめて変えられます。

@pitfalls
- **数式バーが表示されていない**（PC）→ 表示 タブ →「数式バー」にチェック。最初にオンにしておく
- **「任意」の型のまま進める** → 並べ替えが文字の順になる（"10" が "9" より前に来る）など、後でおかしな結果に
- **元の Excel シートを直接直す** → パワークエリの意味がなくなる。直すのはクエリの中で
- **閉じて読み込むのを忘れる** → エディターで整形しても、シートには反映されていない

@steps pq1a
1. まず整数にする3列（注文ID・数量・単価）の列見出しを順にタップして、まとめて選ぶ
2. 開いたメニュー（または「選択: …」の「メニュー」）から「型の変更」→「整数」
3. 選択解除してから、日付 列を選び「型の変更」→「日付」
4. 残りの4列（顧客名・商品名・カテゴリ・担当者）を選んで「テキスト」
5. 列見出しのアイコンが 123 / 📅 / ABC になったか確認して採点（1ステップにまとめても、何ステップに分けても OK）

@@lesson pq2
@image
データ型は **「この列には何が入っているか」というラベル** です。

倉庫の在庫表で「在庫数」の列に、12、150 といった数字に混じって「欠品」「確認中」と書かれたセルがあったとします。人間なら意味が分かりますが、コンピューターに「この列は数（整数）だ」と教えると、「欠品」は数に変換できないので **Error（エラー）** になります。

これは悪いことではなく、**「ここにおかしな値がありますよ」という警告ランプ** です。エラーを見つけたら、「行ごと捨てる」か「0 などに置き換える」かを、業務の意味で決めて処理します。

@detail
### 1. 型を変えると、変換できない値は Error になる
変更前（任意）：
| 商品 | 倉庫 | 在庫数 |
|---|---|---|
| コーヒー豆 | 東京 | 12 |
| クッキー | 東京 | 欠品 |
| ノート | 大阪 | 確認中 |

在庫数を「整数」に変更すると：
| 商品 | 倉庫 | 在庫数 |
|---|---|---|
| コーヒー豆 | 東京 | 12 |
| クッキー | 東京 | **Error** |
| ノート | 大阪 | **Error** |

- 行は**消えない**。そのセルだけが Error になる
- Error のセルをタップすると理由が見られる（DataFormat.Error: 数値に変換できませんでした）

### 2. 対処①：エラーの行を削除する
「確認中の在庫は集計しない」なら、エラーのある行ごと取り除きます。
```powerquery
= Table.RemoveRowsWithErrors(#"変更された型", {"在庫数"})
```
| 商品 | 倉庫 | 在庫数 |
|---|---|---|
| コーヒー豆 | 東京 | 12 |

（Error だった2行がなくなる）

### 3. 対処②：エラーを別の値に置き換える
「欠品＝在庫0」とみなすなら、エラーを 0 に置き換えます。行数は変わりません。
```powerquery
= Table.ReplaceErrorValues(#"変更された型", {{"在庫数", 0}})
```
| 商品 | 倉庫 | 在庫数 |
|---|---|---|
| コーヒー豆 | 東京 | 12 |
| クッキー | 東京 | **0** |
| ノート | 大阪 | **0** |

> どちらが正しいかは**業務のルール次第**です。迷ったら、どんな値がエラーになったかを先に確認してから決めましょう。

### 4. ステップの順番が大事
「型の変更」→「エラーの削除」の順です。型を変える前はエラーがまだ起きていないので、先に「エラーの削除」をしても何も消えません。適用したステップは**上から順番に**実行されることを意識しましょう。

### 5. テキストにすべき「数字」
社員番号「00123」、郵便番号、電話番号は数字に見えますが、**計算しないので「テキスト」** にします。整数にすると先頭の 0 が消えて「123」になってしまいます。

### 6. 自動の「変更された型」ステップ
Excel で CSV などを読み込むと、自動で「変更された型」ステップが付きます。便利ですが、式の中に列名が書き込まれるため、元データの列名が変わると「列 '○○' が見つかりませんでした」というエラーになります。おかしな型が付いていたら、そのステップを削除して自分で付け直して構いません。

@pitfalls
- **エラーの削除を型の変更より前にする** → まだエラーが起きていないので何も消えない
- **列を選ばずにエラーの削除** → すべての列が対象。意図しない列のエラーまで行ごと消える
- **ID や郵便番号を整数にする** → 先頭の 0 が消える
- **Error を見落としたまま読み込む** → シートでは空欄になり、集計値が合わない原因に
- **小数を含む列を「整数」にする** → 四捨五入されてしまう。単価などは「10進数」

@steps pq2a
1. 在庫数の列見出しをタップ →「型の変更」→「整数」（「欠品」「確認中」の2つが Error になるのを確認）
2. 在庫数を選んだまま、ホームの「エラーの削除」
3. 行が5行になったことを確認して採点

@steps pq2b
1. pq2a と同じく、在庫数を「整数」に変更する
2. 在庫数を選んで、変換 タブの「エラーの置換」→ 値に 0
3. 行は7行のまま、Error が 0 になったことを確認して採点

@@lesson pq3
@image
列の整理は **「引き出しの整理整頓」** です。

システムから出力したデータには、分析に使わない列がたくさん付いてきます。必要な列だけを残し、分かりやすい名前を付け、見たい順に並べる ── これだけで、その後の作業がぐっと楽になります。

ポイントは、「消す列を選ぶ」より **「残す列を選ぶ」（他の列の削除）** 方が、来月元データに列が増えたときに強い、ということです。

@detail
### 1. 列の削除 と 他の列の削除
元の列：注文ID・日付・顧客名・商品名・カテゴリ・数量・単価・担当者

**列の削除**（注文ID・カテゴリ・担当者を選んで削除）
```powerquery
= Table.RemoveColumns(ソース,{"注文ID", "カテゴリ", "担当者"})
```
**他の列の削除**（日付・顧客名・商品名・数量・単価を選んで実行）
```powerquery
= Table.SelectColumns(ソース,{"日付", "顧客名", "商品名", "数量", "単価"})
```
結果は同じ5列ですが、来月の元データに「備考」列が増えたら？
| 方法 | 来月の結果 |
|---|---|
| 列の削除 | 備考 が**残ってしまう** |
| 他の列の削除 | 指定した5列だけ（備考は入らない） |

> 「他の列の削除」では、**選んだ順番が結果の列の順番**になります（演習で順番を指定されたら、その順にタップ）。

### 2. 名前の変更
列見出しのメニュー →「名前の変更」。
```powerquery
= Table.RenameColumns(ソース,{{"顧客名", "取引先"}, {"数量", "販売数"}})
```
`{"旧", "新"}` の組がいくつも並ぶ形です。1ステップでまとめて変えても、2ステップに分けても結果は同じです。

### 3. 並べ替え
列見出しのメニュー →「昇順」（小さい順・あいうえお順・古い順）／「降順」（大きい順・新しい順）。
```powerquery
= Table.Sort(#"名前が変更された列",{{"販売数", Order.Descending}})
```
ビフォー → アフター（販売数の降順）：
| 商品名 | 販売数 | | 商品名 | 販売数 |
|---|---|---|---|---|
| コーヒー豆 | 3 | → | ボールペン | 50 |
| クッキー | 10 | | ファイル | 40 |
| ノート | 20 | | ポテトチップス | 30 |

### 4. 2つの列で並べ替える（第2キー）
「カテゴリ順に並べ、同じカテゴリの中では単価の高い順」は、**カテゴリを昇順 → 続けて単価を降順** と2回操作します。2回目の並べ替えは、1回目の式に追加されます。
```powerquery
= Table.Sort(ソース,{{"カテゴリ", Order.Ascending}, {"単価", Order.Descending}})
```
| カテゴリ | 単価 |
|---|---|
| ドリンク | 1500 |
| ドリンク | 600 |
| ドリンク | 150 |
| 菓子 | 450 |
| 菓子 | 300 |
並べ替えの優先順位は **{ } の中の順番** です（先に書いた方が優先）。

### 5. ステップは「前のステップの名前」でつながっている
```powerquery
#"名前が変更された列" = Table.RenameColumns(ソース, …)
#"並べ替えられた行"   = Table.Sort(#"名前が変更された列", …)
```
各ステップの1つ目の引数が「1つ前のステップの名前」です。途中のステップを削除すると、次のステップが探す名前が消えてエラーになることがあります（このアプリでは自動でつなぎ直します）。

@pitfalls
- **残す列の選ぶ順番** → 他の列の削除は、選んだ順がそのまま列の順になる
- **第2キーを先に並べ替える** → 優先順位が逆になる。「大きな分類 → 細かい分類」の順に操作
- **名前を変えた後に、古い名前で操作する** → 列 '○○' が見つかりません
- **並べ替えの向き** 昇順＝小さい順、降順＝大きい順

@steps pq3a
1. 列見出しを「日付 → 顧客名 → 商品名 → 数量 → 単価」の順にタップして5つ選ぶ
2. ホームの「他の列の削除」（または列メニューの「他の列の削除」）
3. 列が5つ、この順番になっていれば採点

@steps pq3b
1. 顧客名の列見出しをタップ →「名前の変更」→「取引先」
2. 選択を解除し、数量 →「名前の変更」→「販売数」
3. 販売数を選んで「降順で並べ替え」
4. 列名が変わり、販売数の大きい順になっていれば採点

@steps pq3c
1. カテゴリの列見出し →「昇順で並べ替え」
2. 続けて（ステップを選び直さずに）単価の列見出し →「降順で並べ替え」
3. 数式バーの Table.Sort に2つの指定が並んでいることを確認して採点

@@lesson pq4
@image
行のフィルターは **「ふるいにかける」** 作業です。条件に合う行だけが網に残り、合わない行は落ちます。

Excel のオートフィルターと見た目は似ていますが、大きな違いがあります。Excel のフィルターは「見えなくするだけ」なのに対し、パワークエリのフィルターは **結果の表から本当に取り除きます**。しかも条件が記録されるので、来月のデータにも自動で同じふるいがかかります。

@detail
### 1. 値の一覧で選ぶ
列見出し → フィルター →「値の一覧」で、残したい値にチェック。
```powerquery
= Table.SelectRows(ソース, each ([カテゴリ] = "菓子"))
```
`each` は「**各行について**」、`[カテゴリ]` は「**その行のカテゴリ列の値**」。全体で「各行について、カテゴリが菓子なら残す」と読みます。

### 2. 条件で選ぶ（数値・テキスト・日付フィルター）
「数量が10以上」は、数値フィルター →「以上」→ 10。
```powerquery
= Table.SelectRows(#"フィルターされた行", each [数量] >= 10)
```
| 書き方 | 意味 |
|---|---|
| `=` / `<>` | 等しい / 等しくない |
| `>` / `>=` | より大きい / 以上 |
| `<` / `<=` | より小さい（未満）/ 以下 |
| `and` / `or` | かつ / または |
| `Text.Contains([列], "東京")` | 東京 を含む |

2つの条件を1回で書くこともできます。
```powerquery
each [カテゴリ] = "菓子" and [数量] >= 10
```
ビフォー（16行）→ アフター：
| 商品名 | カテゴリ | 数量 |
|---|---|---|
| クッキー | 菓子 | 10 |
| チョコレート | 菓子 | 12 |
| ポテトチップス | 菓子 | 30 |
| チョコレート | 菓子 | 20 |

### 3. 日付で絞るには、先に日付型にする
日付列が「任意（文字）」のままだと、`#date(2026, 5, 1)` と比べられません。
1. 日付列 →「型の変更」→「日付」
2. 日付フィルター →「以降」→ 2026/5/1
```powerquery
= Table.SelectRows(#"変更された型", each [日付] >= #date(2026, 5, 1))
```
`#date(年, 月, 日)` が M 言語での日付の書き方です。

### 4. 重複の削除
全く同じ内容の行が2回入っているとき：
| 顧客ID | 顧客名 |
|---|---|
| C03 | みなと文具店 |
| C03 | みなと文具店 |
列を選ばずに（または全部の列を選んで）「重複の削除」→ 1行になります。
```powerquery
= Table.Distinct(ソース)
```
特定の列（顧客ID など）を選んでから実行すると、**その列だけ**で重複を判定し、最初に出てくる行が残ります。

### 5. 上位の行の保持（トップN）
「数量の多い順に並べ替え」→「上位の行の保持」→ 3、で売上トップ3が作れます。**並べ替えてから**保持するのがポイントです。
```powerquery
= Table.FirstN(#"並べ替えられた行",3)
```

@pitfalls
- **大文字・小文字・空白の違い** パワークエリの比較は厳密。"菓子" と "菓子 "（空白付き）は別の値
- **日付型にせずに日付で比較** → エラーになる
- **並べ替えずに上位の行の保持** → 単に先頭の3行になる
- **重複の削除の前に表記ゆれを直していない** → 「青葉商事」と「 青葉商事」は別の行として残る
- **and と or の取り違え** 「菓子 かつ 10以上」は and

@steps pq4a
1. カテゴリの列見出し →「フィルター」→ 値の一覧で「選択解除」→「菓子」だけにチェック → OK
2. 選択を解除し、数量の列見出し →「フィルター」→「数値フィルター」タブ
3. 条件1を「以上」・値 10 にして OK
4. 4行になったことを確認して採点（1つのステップに and で書いても OK）

@steps pq4b
1. 列を何も選ばない状態で、ホームの「重複の削除」
2. 行数が 8 → 7 になったことを確認して採点

@steps pq4c
1. 日付の列見出し →「型の変更」→「日付」（アイコンが 📅 に）
2. 日付の列見出し →「フィルター」→ 日付フィルター → 条件「以降」・値 2026/5/1
3. 5月の行（4行）だけになったことを確認して採点

@steps pq4d
1. 数量の列見出し →「降順で並べ替え」
2. ホームの「上位の行の保持」→ 3
3. 数量の多い3行だけになったか確認して採点

@@lesson pq5
@image
手入力のデータには、目には見えにくい **「表記ゆれ」** がたくさん隠れています。

- 「 青葉商事」（先頭に空白）と「青葉商事」
- 「Info@Aoba」と「info@aoba」
- 「山田　太郎」（全角スペース）と「山田 太郎」（半角スペース）

人間には同じに見えても、コンピューターにとっては**別の文字列**です。このままでは重複の削除やマージ（突き合わせ）がうまくいきません。今日はこれを **「洗濯」** して、そろった形にする方法を学びます。

@detail
### 1. トリム：前後の空白を消す
| 変更前 | → | 変更後 |
|---|---|---|
| " 青葉商事" | | "青葉商事" |
| "さくら食品 " | | "さくら食品" |
| "法人 " | | "法人" |
列を選んで 変換 → 書式 →「トリム」。
```powerquery
= Table.TransformColumns(ソース,{{"顧客名", Text.Trim, type text}})
```
`Table.TransformColumns` は「指定した列の**すべての値**に、指定した関数を1つずつ適用する」という意味です。ここでは関数 `Text.Trim` を顧客名の各セルに適用しています。複数の列を選んで実行すると `{ }` の中に列が並びます。

> トリムが消すのは**前後**だけ。「山田　太郎」の**間**の全角スペースは残ります。

### 2. 大文字・小文字
| 操作 | 関数 | 例 |
|---|---|---|
| 小文字 | Text.Lower | Info@Aoba → info@aoba |
| 大文字 | Text.Upper | abc → ABC |
| 各単語の先頭を大文字 | Text.Proper | sato hanako → Sato Hanako |
メールアドレスは大文字小文字を区別しない（ことが多い）ので、小文字にそろえておくと突き合わせが確実になります。

### 3. 値の置換
列を選んで「値の置換」→ 検索する値・置換後の値。
```powerquery
= Table.ReplaceValue(ソース,"　"," ",Replacer.ReplaceText,{"顧客名"})
```
引数の意味：「ソースの表で、"　"（全角スペース）を " "（半角スペース）に、**部分一致で**（ReplaceText）、顧客名 列だけ置き換える」。

| 変更前 | → | 変更後 |
|---|---|---|
| 山田　太郎 | | 山田 太郎 |

### 4. 部分一致と完全一致
| 種類 | 関数 | 「東京」→「東京都」に置換したとき「東京都」のセルは |
|---|---|---|
| 部分一致（既定） | Replacer.ReplaceText | 「東京**都**都」になってしまう |
| 完全一致 | Replacer.ReplaceValue | 変わらない（セル全体が「東京」のときだけ置換） |
ダイアログの「セルの内容全体を一致させる」にチェックすると完全一致になります。

### 5. どの順番でやる？
「全角→半角の置換」と「トリム」はどちらが先でも結果は同じです。ただし、**重複の削除やマージの前に**整形を済ませておくのが鉄則です。

@pitfalls
- **トリムで間のスペースも消えると思う** → 消えない。値の置換で対応
- **部分一致の置換で、意図しない所まで変わる** → 完全一致のオプション
- **全角スペースの入力** 検索する値に全角スペースを入れるには、日本語入力でスペースキー
- **書式は「テキスト」の列だけ** 数値列にトリムをかけると型がテキストになる

@steps pq5a
1. 顧客名と区分の列見出しをタップして2列選ぶ
2. 変換 タブ →「書式」→「トリム」
3. 選択を解除し、メールの列見出しをタップ → 書式 →「小文字」
4. 1行目の顧客名が「青葉商事」、メールが小文字になったか確認して採点

@steps pq5b
1. 顧客名の列見出し →「値の置換」
2. 検索する値に全角スペース（日本語入力のスペース）、置換後に半角スペースを入れて OK（完全一致のチェックは外したまま）
3. もう一度 顧客名 → 書式 →「トリム」（順番は逆でも OK）
4. 「山田 太郎」が半角スペースになり、前後の空白が消えたか確認して採点

@@lesson pq6
@image
1つのセルに **2つ以上の情報が詰め込まれている** ことがよくあります。

- 「東京都 千代田区丸の内1-1」→ 都道府県 と それ以降
- 「5:とても満足」→ 点数 と ラベル
- 「価格;品質;デザイン」→ 複数の選択肢

これを **ハサミで切り分ける** のが「列の分割」です。切り分けた後で、どちら向き（横＝列、縦＝行）に並べるかで、その後の集計のしやすさが変わります。

@detail
### 1. 区切り記号で列に分割
住所 列を選んで「列の分割」→ 区切り記号「スペース」。
```powerquery
= Table.SplitColumn(ソース, "住所", Splitter.SplitTextByDelimiter(" ", QuoteStyle.Csv), {"住所.1", "住所.2"})
```
| 住所 | → | 住所.1 | 住所.2 |
|---|---|---|---|
| 東京都 千代田区丸の内1-1 | | 東京都 | 千代田区丸の内1-1 |
| 大阪府 大阪市北区梅田2-2 | | 大阪府 | 大阪市北区梅田2-2 |
- 新しい列は元の列の**位置**にでき、名前は「元の列名.1」「.2」
- 最後の `{"住所.1", "住所.2"}` が新しい列名。後で「名前の変更」をしても、この部分を直接書き換えても OK

### 2. 分割の位置
| 選択肢 | 「A B C」を空白で分けると |
|---|---|
| 区切り記号の出現ごと | A ／ B ／ C（3列） |
| 一番左の区切り記号 | A ／ B C（2列） |
| 一番右の区切り記号 | A B ／ C（2列） |

### 3. 「5:とても満足」を点数とラベルに
区切り記号に「カスタム」で `:` を指定します。
| 満足度 | → | 満足度点 | 満足度ラベル |
|---|---|---|---|
| 5:とても満足 | | "5" | とても満足 |
分けた「5」はまだ**テキスト**です。平均点を出したいなら、満足度点 を「整数」に型変更します。

### 4. 行に分割（縦に並べる）
「価格;品質」のように**項目数が行ごとに違う**ものは、列に分けると列数がバラバラになってしまいます。そこで詳細設定で **「行」に分割** します。
| 回答ID | 良かった点 | → | 回答ID | 良かった点 |
|---|---|---|---|---|
| 1 | 価格;品質 | | 1 | 価格 |
| 2 | 品質 | | 1 | 品質 |
| | | | 2 | 品質 |
回答1は2行に増えます。こうしておけば、後で「良かった点」でグループ化して **項目ごとの件数** を数えられます。

### 5. 抽出（取り出す）
分割ではなく、一部分だけ取り出したいときは「抽出」。
| 操作 | M | 例 |
|---|---|---|
| 最初の文字 | Text.Start(値, 3) | "東京都千代田区" → "東京都" |
| 区切り記号の前 | Text.BeforeDelimiter(値, ":") | "5:とても満足" → "5" |
| 区切り記号の後 | Text.AfterDelimiter(値, ":") | → "とても満足" |
「変換」タブの抽出は列を書き換え、「列の追加」タブの抽出は新しい列を作ります。

@pitfalls
- **分割した数字がテキストのまま** → 計算するなら型変更（演習 pq6b は型も採点）
- **区切り記号の種類** 全角スペースと半角スペース、全角：と半角: は別物
- **項目数がバラバラなのに列に分割** → 列が多すぎたり、null だらけになる。行に分割を検討
- **分割後の列名** 演習で名前を指定されたら、名前の変更を忘れずに

@steps pq6a
1. 住所の列見出し →「列の分割」
2. 区切り記号「スペース」、区切り記号の出現ごと、方向「列」で OK
3. できた 住所.1 を「都道府県」、住所.2 を「市区町村」に名前変更
4. 都道府県・市区町村が元の住所の位置にあるか確認して採点

@steps pq6b
1. 満足度の列見出し →「列の分割」→ 区切り記号「カスタム」に `:`（半角コロン）
2. できた2列を「満足度点」「満足度ラベル」に名前変更
3. 満足度点 →「型の変更」→「整数」
4. 満足度点のアイコンが 123 になったか確認して採点

@steps pq6c
1. 良かった点の列見出し →「列の分割」
2. 区切り記号「セミコロン」、分割の方向（詳細設定）を「行」にして OK
3. 行数が 6 → 10 に増え、1行に1項目になったか確認して採点

@@lesson pq7
@image
**カスタム列**は、Excel で表の右に `=C2*D2` と式を入れてオートフィルする作業と同じです。違いは、パワークエリでは **セル番地ではなく [列名] で書く** こと。だから行が増えても、列の位置が変わっても、式を直す必要がありません。

**条件列**は、Excel の IF 関数にあたります。「金額が1万円以上なら大口」のような分類を、ダイアログで条件を並べるだけで作れます。

@detail
### 1. カスタム列の作り方
列の追加 →「カスタム列」→ 新しい列名「金額」、式 `[数量] * [単価]`。
```powerquery
= Table.AddColumn(ソース, "金額", each [数量] * [単価])
```
| 商品名 | 数量 | 単価 | → 金額 |
|---|---|---|---|
| コーヒー豆 | 3 | 1500 | 4500 |
| クッキー | 10 | 450 | 4500 |
| ノート | 20 | 220 | 4400 |
読み方：「ソースの表に『金額』列を追加する。中身は、各行（each）の 数量 × 単価」。
> ダイアログでは `each` は自動で付くので、`[数量] * [単価]` だけ書けば OK。右の「使用できる列」をタップすると [列名] が挿入されます。

### 2. 文字をつなげる
文字の連結は **`&`** です（Excel と同じ。`+` はエラー）。
```powerquery
each [氏名] & "（" & [部署] & "）"
```
→「田中 誠（営業部）」。
数値をつなげるときは、先に文字にします：`"No." & Text.From([番号])`

### 3. 条件分岐 if then else
```powerquery
each if [数量] * [単価] >= 10000 then "大口"
     else if [数量] * [単価] >= 3000 then "中口"
     else "小口"
```
| 金額 | 判定の流れ | 結果 |
|---|---|---|
| 15000 | 10000以上 → はい | 大口 |
| 4500 | 10000以上 → いいえ、3000以上 → はい | 中口 |
| 2400 | どちらも いいえ | 小口 |
**上から順に**調べ、最初に当てはまったものが結果になります。だから2つ目の条件に「10000未満」と書かなくても大丈夫です。
- `if … then … else …` の **else は必ず必要**（Excel の IF と違い省略できない）
- 「条件列」ダイアログで作ると、この式が自動で作られます

### 4. 関数を使う
| やりたいこと | 式 |
|---|---|
| 年を取り出す | `Date.Year([入社日])` |
| 文字数 | `Text.Length([商品名])` |
| 四捨五入 | `Number.Round([金額] * 1.1)` |
| 含むか | `Text.Contains([住所], "東京")` |
関数名は**大文字・小文字を区別**します（`date.year` はエラー）。

### 5. 日付の関数は日付型の列で
`Date.Year([入社日])` は、入社日 が日付型でないとエラーになります。先に型を変えるか、列の追加 → 日付 →「年」を使います（日付型の列を選んでいる必要があります）。

@pitfalls
- **文字の連結に +** → Expression.Error。`&` を使う
- **else の書き忘れ** → 構文エラー
- **[列名] のつづり違い** → 「フィールド '○○' が見つかりませんでした」
- **null を含む計算** → 結果も null（空白）になる
- **関数名の大文字小文字** `Text.Upper` は OK、`text.upper` はエラー

@steps pq7a
1. 列の追加 タブ →「カスタム列」
2. 新しい列名に「金額」、式に `[数量] * [単価]`（列名のチップをタップすると入力できる）
3. OK → 一番右に金額の列ができたか確認して採点

@steps pq7b
1. 列の追加 →「カスタム列」、列名「規模」
2. 式は if を2段：「数量×単価が10000以上なら"大口"、そうでなく3000以上なら"中口"、それ以外"小口"」を if … then … else if … then … else … で書く
3. 文字列は " " で囲む。金額列は作らない（規模だけ追加）
4. 1行目（4500）が「中口」になっているか確認して採点

@steps pq7c
1. 列の追加 →「カスタム列」、列名「表示名」
2. 式は [氏名] と全角の「（」、[部署]、「）」を & でつなぐ
3. 「田中 誠（営業部）」の形になっているか確認して採点

@steps pq7d
1. 入社日の列見出し →「型の変更」→「日付」
2. 入社日を選んだまま 列の追加 →「日付」→「年」（またはカスタム列で `Date.Year([入社日])`）
3. 列名を「入社年」にする（日付メニューから作ると「年」になるので名前の変更を）
4. 入社年が 2012 などの数値になっているか確認して採点

@@lesson pq8
@image
現場から届く Excel には、**人が見るための飾り** がたくさん付いています。タイトル行、作成日、空行、結合セル…。人には見やすくても、データとしては扱いにくい形です。

今日は、そうした「報告書の形」を「データベースの形」（1行目が見出し、2行目から1件ずつのデータ、空欄なし）に整える技を学びます。毎月同じ形式で届くなら、一度クエリを作れば次からは更新するだけです。

@detail
### 1. 報告書の形を読み込むと…
| Column1 | Column2 | Column3 |
|---|---|---|
| 支店別 売上報告書 | null | null |
| 作成日: 2026/06/01 | null | null |
| null | null | null |
| 支店 | 売上 | 目標 |
| 東京 | 1,250 | 1,200 |
| 大阪 | 980 | 1,000 |
見出しが4行目にあるので、列名が Column1〜3 になっています。

### 2. 上位の行の削除
ホーム →「上位の行の削除」→ 3。
```powerquery
= Table.Skip(ソース,3)
```
| Column1 | Column2 | Column3 |
|---|---|---|
| 支店 | 売上 | 目標 |
| 東京 | 1,250 | 1,200 |

### 3. 1行目をヘッダーとして使用
ホーム →「1行目をヘッダーに」。
```powerquery
= Table.PromoteHeaders(#"削除された上位の行", [PromoteAllScalars=true])
```
| 支店 | 売上 | 目標 |
|---|---|---|
| 東京 | 1,250 | 1,200 |
| 大阪 | 980 | 1,000 |

### 4. 型の変更
「1,250」はカンマ付きの**文字**です。売上・目標を「整数」にすると 1250（数）になり、計算できるようになります（日本語の環境ではカンマは桁区切りとして読まれます）。

この **「行の削除 → ヘッダー → 型」の順番** が大切です。先に型を変えようとすると、まだ「支店別 売上報告書」などの文字が混ざっているのでエラーだらけになります。

### 5. 結合セルの名簿 → フィル（下へ）
| 部署 | 氏名 | | 部署 | 氏名 |
|---|---|---|---|---|
| 営業部 | 田中 | → | 営業部 | 田中 |
| null | 伊藤 | | **営業部** | 伊藤 |
| null | 渡辺 | | **営業部** | 渡辺 |
| 総務部 | 小林 | | 総務部 | 小林 |
| null | 加藤 | | **総務部** | 加藤 |
部署 列を選んで 変換 →「フィル」→「下へ」。**null（空）のセルを、すぐ上の値で埋めます**。
```powerquery
= Table.FillDown(ソース,{"部署"})
```

### 6. null を特定の値に置き換える
「役職が空なら『一般』」は、値の置換で検索する値に **null** と入力します（完全一致の置換になる）。
```powerquery
= Table.ReplaceValue(#"下方向へコピー済み",null,"一般",Replacer.ReplaceValue,{"役職"})
```

@pitfalls
- **順番を間違える**（型 → 行の削除）→ エラーが大量に出る
- **削除する行数の数え間違い** 見出しが何行目か、プレビューの行番号で確認
- **フィルは null だけを埋める** 空文字 "" やスペースのセルは埋まらない（先に置換で null に）
- **null を "null" という文字で置換** 演習画面の置換ダイアログでは null と入力すれば OK

@steps pq8a
1. ホーム →「上位の行の削除」→ 3（見出しの「支店・売上・目標」が1行目に来る）
2. ホーム →「1行目をヘッダーに」
3. 売上と目標の2列を選び「型の変更」→「整数」
4. 1,250 が 1250 になったか確認して採点

@steps pq8b
1. 部署の列見出し → 変換 →「フィル（下へ）」（または列メニューの「フィル（下へ）」）
2. 選択を解除し、役職の列見出し →「値の置換」→ 検索する値に null、置換後に 一般
3. 部署の空欄がなくなり、役職の空欄が「一般」になったか確認して採点
