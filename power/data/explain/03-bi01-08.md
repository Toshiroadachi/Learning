@@lesson bi1
@image
Power BI は **「データを材料に、見るたびに最新になるレポートを作る台所」** です。

1. **材料を仕入れる**（Excel・CSV・システムからデータを取得し、Power Query で下ごしらえ）
2. **レシピを書く**（データモデルとメジャー。「売上合計」「前年比」などの計算式）
3. **盛り付ける**（グラフや表のレポート）
4. **お店に出す**（Power BI Service でチームに共有、毎日自動で更新）

Excel のピボットテーブルを、もっと大きなデータで、もっと自由に、みんなで使えるようにしたもの、と考えるとイメージしやすいです。

@detail
### 1. Excel のピボットとの違い
| | Excel ピボット | Power BI |
|---|---|---|
| 扱える行数 | 約104万行まで（シート） | 数千万行も可能 |
| 表の数 | 基本は1つ | 複数の表をつないで使う |
| 計算 | 集計方法を選ぶ | **DAX** で自由に式を書く |
| 共有 | ファイルを送る | Web・スマホで共有、自動更新 |

### 2. メジャー＝「どこに置いても、その場の条件で計算し直す式」
```dax
売上金額 = SUM(売上[金額])
```
- `売上金額` … メジャーの名前（自分で決める）
- `SUM(…)` … 合計する関数
- `売上[金額]` … **売上テーブルの金額列**（テーブル名[列名]）

このメジャーをマトリックスに置き、行に「商品[カテゴリ]」を入れると：
| カテゴリ | 売上金額 |
|---|---|
| ドリンク | 236,730 |
| 文具 | 108,420 |
| 菓子 | 190,224 |
| 雑貨 | 53,880 |
| **合計** | **589,254** |
式は1つなのに、行ごとに違う値になっています。

### 3. なぜ行ごとに値が変わるのか ― フィルターコンテキスト
「ドリンク」の行では、Power BI が自動で **「カテゴリ＝ドリンク の売上だけを見る」という条件（フィルター）** をかけてから SUM を計算しています。
| 行 | かかっている条件 | 計算 |
|---|---|---|
| ドリンク | カテゴリ＝ドリンク | ドリンクの金額だけ合計 |
| 文具 | カテゴリ＝文具 | 文具の金額だけ合計 |
| 合計 | 条件なし | 全部の金額を合計 |
この「その場でかかっている条件」を **フィルターコンテキスト** と呼びます。DAX でいちばん大事な考え方なので、この先何度も出てきます。

### 4. このアプリの演習画面の見方
- **📊 レポート**：マトリックス（行・列の見出しと、メジャーの値）
- **▦ テーブル**：読み込んだデータの中身（Excel のシートのような表示）
- **🔗 モデル**：テーブルどうしのつながり
- 下のエディターに式を書き、「メジャーを確定」でマトリックスに反映、「採点する」で答え合わせ

@pitfalls
- **列名だけ書く** `SUM(金額)` → テーブル名も付けて `SUM(売上[金額])`
- **全角のカッコ・記号** `SUM（売上[金額]）` → エラー。半角で
- **メジャー名と列名を混同** 自分で作るのはメジャー名。式の中で使うのは既存の列
- **合計行が各行の足し算だと思う** 合計行は「条件なし」で計算し直した値（今は足し算と同じだが、比率などでは違ってくる）

@steps bi1a
1. 合計したいのは「売上」テーブルの「金額」列
2. 合計の関数は SUM。引数は テーブル名[列名] の形
3. エディターに `SUM(売上[金額])` と入力し、「メジャーを確定」でカテゴリごとの値を確認してから採点

@@lesson bi2
@image
Power BI では、**1つの大きな表** ではなく、**役割ごとの複数の表をつないで** 使います。

コンビニのレシートの束を想像してください。
- レシート1枚1枚（いつ・誰が・何を・何個） … **ファクト（事実）の表**＝売上
- 商品の一覧（名前・カテゴリ・原価） … **ディメンション（切り口）の表**＝商品
- お客さんの一覧（地域・法人/個人） … ディメンション＝顧客
- カレンダー（年・月・四半期） … ディメンション＝カレンダー

レシートには商品IDしか書かず、商品の詳しい情報は商品表を見る。この **中心に事実、周りに切り口** の形を、星の形に見立てて **スター スキーマ** と呼びます。

@detail
### 1. このアプリのモデル
```
            商品（10行）
               │1
               │
顧客（8行）─1──*─ 売上（207行）─*──1─ カレンダー（546日）
```
- 売上 1行 = 1注文。数量・単価・金額と、各表のキー（商品ID・顧客ID・日付）
- 「1」と「*（多）」：1つの商品に、売上の行はたくさんある → **1対多**

### 2. フィルターは「1」から「*」へ流れる
マトリックスの行に **顧客[地域]** を置いて、売上の数量を合計すると：
| 地域 | 数量合計 |
|---|---|
| 名古屋 | 206 |
| 大阪 | 506 |
| 札幌 | 266 |
| 東京 | 651 |
| 福岡 | 192 |
何が起きているか：
1. 「東京」の行 → 顧客テーブルが **地域＝東京 の顧客だけ** に絞られる
2. リレーションシップを通って、売上テーブルも **その顧客の注文だけ** に絞られる
3. 絞られた売上で SUM(売上[数量]) を計算

顧客表に数量の列はないのに、地域別に集計できるのは、**フィルターが 顧客 → 売上 に流れる** からです。

### 3. 逆向きには流れない（単方向）
行に 顧客[地域] を置き、`COUNTROWS(商品)`（商品の行数）を表示すると、どの地域も **10** になります。
- 顧客 → 売上 には流れる
- 売上 → 商品 には流れない（矢印は 商品 → 売上 の向き）
「東京の人が買った商品の数」が欲しいなら、売上を通して数える別の式（DISTINCTCOUNT(売上[商品ID]) など）を使います。

### 4. 行と列に別々の切り口
マトリックスの行に 商品[カテゴリ]、列に カレンダー[年] を置くと、各セルには **2つの条件が同時に** かかります。
| カテゴリ | 2025 | 2026 | 合計 |
|---|---|---|---|
| ドリンク | 53件 | 19件 | 72件 |
「ドリンク × 2025」のセル ＝ カテゴリ＝ドリンク **かつ** 年＝2025 の売上だけを数える。

### 5. COUNTROWS ― 行数を数える
```dax
注文件数 = COUNTROWS(売上)
```
引数は **テーブル**（列ではない）。売上テーブルの見えている行の数＝注文件数です。

@pitfalls
- **1つの大きな表に全部まとめる** → 集計が遅く、重複も起きやすい。ファクトとディメンションに分ける
- **COUNTROWS に列を渡す** `COUNTROWS(売上[注文ID])` → テーブルを渡す
- **ディメンションの表を数える** → フィルターの向きによっては変わらない（単方向）
- **日付で集計するのに日付テーブルがない** → タイムインテリジェンス（第11回）が使えない

@steps bi2a
1. 数量は売上テーブルにある → `SUM(売上[数量])`
2. 確定して、地域ごとに値が違う（フィルターが顧客から売上に流れている）ことを確認して採点

@steps bi2b
1. 注文1件＝売上テーブルの1行
2. 行数を数える関数 COUNTROWS に、テーブル名（売上）を渡す
3. 確定して、カテゴリ×年 の各セルに件数が出ることを確認して採点

@@lesson bi3
@image
DAX の式には2種類あります。

- **計算列**：表の **右に列を1本足す**。Excel の表で、右端の列に `=C2*1.1` を入れて下までコピーするのと同じ。1行ずつ計算され、結果は表に保存されます。
- **メジャー**：表には何も足さない。**ビジュアルに置いたとき、その場の条件で集計する** 式。

たとえるなら、計算列は「レシート1枚ずつに税込金額を書き込む」、メジャーは「レジ締めのときに、その日の合計を計算する」です。

@detail
### 1. 計算列は1行ずつ計算する
売上テーブルに計算列「税込金額」を追加：
```dax
税込金額 = 売上[金額] * 1.1
```
| 注文ID | 金額 | 税込金額 |
|---|---|---|
| 1001 | 360 | 396 |
| 1002 | 1350 | 1485 |
| 1003 | 1620 | 1782 |
式の中の `売上[金額]` は、**その行の** 金額を指します。計算列には「今どの行を計算しているか」という情報があるからです（これを **行コンテキスト** と呼びます）。

### 2. IF で分類する計算列
```dax
規模 = IF(売上[金額] >= 5000, "大口", "通常")
```
- `IF(条件, 真のとき, 偽のとき)` は Excel の IF と同じ
- 作った「規模」列は、スライサーやマトリックスの行に使える（**切り口として使えるのは列だけ**）

### 3. メジャーには「今の行」がない
メジャーで `= 売上[金額]` とだけ書くとエラーになります。
> 列 売上[金額] の単一の値を特定できません

メジャーはマトリックスのセルで計算されますが、そのセルには売上の行が何十行も含まれています。「どの行の金額？」が決まらないので、**SUM などで集計して1つの値にする**必要があります。
```dax
平均単価 = AVERAGE(売上[単価])
```

### 4. 比率は必ずメジャーで
計算列で行ごとの粗利率を作り、合計行で「合計」にすると、比率どうしを足した意味のない数字になります。
| 注文 | 粗利率（行ごと） |
|---|---|
| A | 50% |
| B | 40% |
| 合計（足し算） | **90%** ← おかしい |
メジャーで「全体の粗利 ÷ 全体の売上」を計算すれば、合計行でも正しい比率になります（第6回）。

### 5. 使い分けのまとめ
| やりたいこと | 選ぶもの |
|---|---|
| スライサー・行・列に使う分類（大口/通常、年代） | 計算列 |
| 合計・平均・件数・比率・前年比 | メジャー |
| 迷ったら | メジャー（モデルが軽く、どのビジュアルでも使える） |

@pitfalls
- **メジャーで列をそのまま書く** → 単一の値を特定できないエラー。SUM などで囲む
- **計算列で集計関数だけ書く** `= SUM(売上[金額])` → 全行が同じ値（全体の合計）になる（第10回）
- **IF の文字列のクォート忘れ** `"大口"` のように半角 " で囲む
- **比率を計算列で作る** → 合計行がおかしくなる

@steps bi3a
1. 計算列なので、式の中の 売上[金額] は「その行の金額」
2. `売上[金額] * 1.1` と書いて「列を追加」
3. テーブルタブで、税込金額の列が追加されたことを確認して採点

@steps bi3b
1. IF(条件, 真, 偽) の形を使う
2. 条件は「その行の金額が 5000 以上」、真のとき "大口"、偽のとき "通常"
3. 「列を追加」してテーブルタブで確認してから採点

@steps bi3c
1. メジャーなので、単価の列を集計関数で1つの値にする必要がある
2. 平均は AVERAGE。引数は 売上[単価]
3. 確定してカテゴリごとの平均を確認して採点

@@lesson bi4
@image
DAX の集計関数は、Excel の関数とほとんど同じ名前です。SUM（合計）、AVERAGE（平均）、MIN・MAX（最小・最大）、COUNT（個数）。

ただし1つ大きな違いがあります。Excel は `=SUM(A2:A100)` のように **セル範囲** を指定しますが、DAX は `SUM(売上[金額])` のように **列全体** を指定します。どの行を合計するかは、マトリックスの行やスライサーの条件（フィルターコンテキスト）が自動で決めてくれます。

@detail
### 1. 集計関数の一覧
| 関数 | 意味 | 例 |
|---|---|---|
| SUM(列) | 合計 | SUM(売上[数量]) |
| AVERAGE(列) | 平均 | AVERAGE(売上[単価]) |
| MIN / MAX(列) | 最小 / 最大 | MAX(売上[日付]) |
| COUNTROWS(テーブル) | 行数 | COUNTROWS(売上) |
| DISTINCTCOUNT(列) | **重複を除いた** 個数 | DISTINCTCOUNT(売上[顧客ID]) |

### 2. COUNTROWS と DISTINCTCOUNT の違い
ある月の売上：
| 注文 | 顧客ID |
|---|---|
| 1 | C01 |
| 2 | C02 |
| 3 | C01 |
| 4 | C01 |
- `COUNTROWS(売上)` → **4**（注文件数）
- `DISTINCTCOUNT(売上[顧客ID])` → **2**（買ってくれたお客さんの人数：C01 と C02）

### 3. MAX は日付にも使える
```dax
最終購入日 = MAX(売上[日付])
```
行に 顧客[顧客名] を置くと、顧客ごとに一番新しい購入日が出ます。合計行には全体で一番新しい日付が出ます。

### 4. メジャーからメジャーを使う
作ったメジャーは、別のメジャーの中で **[メジャー名]** と書いて使えます（テーブル名は付けない）。
```dax
売上金額 = SUM(売上[金額])
注文件数 = COUNTROWS(売上)
平均注文金額 = DIVIDE([売上金額], [注文件数])
```
- DIVIDE(分子, 分母) は割り算（第6回で詳しく）
- 小さなメジャーを組み合わせると、式が読みやすく、直しやすくなる

### 5. 書き分けのルール
| 書き方 | 意味 |
|---|---|
| `売上[金額]` | 列（テーブル名を付ける） |
| `[売上金額]` | メジャー（テーブル名を付けない） |
見ただけで「これは列」「これはメジャー」と分かるので、この書き分けが DAX の基本ルールです。

### 6. 空白（BLANK）
データがないセルは 0 ではなく **空白** になります。マトリックスは、すべての値が空白の行を表示しません（例：2026年に買っていない顧客の行は 2026 列が空白）。

@pitfalls
- **お客さんの人数を COUNTROWS で数える** → 注文件数になる。人数は DISTINCTCOUNT
- **メジャーにテーブル名を付ける** `売上[売上金額]` → 動くこともあるが、列と区別がつかなくなる
- **COUNT と COUNTROWS** COUNT は列の「数値の個数」、COUNTROWS はテーブルの行数
- **割り算に / を使う** 0 で割ると ∞ やエラー。DIVIDE を使う

@steps bi4a
1. 「顧客ID の重複を除いた数」＝ 買ってくれた顧客の人数
2. 関数は DISTINCTCOUNT。引数は 売上[顧客ID]
3. 確定して、カテゴリ×年 のセルに人数が出ることを確認して採点

@steps bi4b
1. 「最後の購入日」＝ 売上の日付の最大値
2. MAX の引数に 売上[日付]
3. 確定して、顧客ごとに日付が出ることを確認して採点

@steps bi4c
1. 既にあるメジャー [売上金額] と [注文件数] を使う（[ ] だけで書く）
2. 割り算は DIVIDE(分子, 分母)。分子が売上金額、分母が注文件数
3. 確定して、法人・個人の1注文あたりの金額を確認して採点

@@lesson bi5
@image
**SUMX** は「1行ずつ計算してから、全部を合計する」関数です。

レシートの束にたとえると、SUM は「レシートに書いてある合計金額を足す」。SUMX は「レシート1枚ずつ **数量 × 単価 を計算してから** 足す」です。元データに「金額」列がなくても、その場で行ごとに計算して合計できます。

**RELATED** は、レシート（売上）に書いてある商品IDから、**商品表の情報（原価など）を引いてくる** 関数で、Excel の VLOOKUP のような役割です。

@detail
### 1. SUM ではできないこと
売上に「数量」と「単価」はあるが「金額」がないとします。
| 注文 | 数量 | 単価 |
|---|---|---|
| A | 2 | 100 |
| B | 3 | 50 |
- 正しい売上金額：2×100 + 3×50 = **350**
- `SUM(数量) * SUM(単価)`：5 × 150 = **750**（間違い！）
「掛けてから足す」と「足してから掛ける」は違う結果になります。

### 2. SUMX の動き
```dax
売上金額X = SUMX(売上, 売上[数量] * 売上[単価])
```
| ステップ | 動き |
|---|---|
| 1 | 売上テーブル（見えている行）を1行ずつ回る |
| 2 | 各行で `数量 × 単価` を計算 → 200, 150 |
| 3 | 全部を合計 → 350 |
2つ目の引数の中では、計算列と同じように **「今の行」** があるので、`売上[数量]` がその行の値になります（**行コンテキスト**）。

> マトリックスの「ドリンク」の行では、SUMX が回る売上テーブルは「ドリンクの注文だけ」に絞られています。フィルターコンテキストで絞られた行を、行コンテキストで1行ずつ計算する ── この2つの組み合わせが DAX の基本です。

### 3. RELATED ― 関連する表から値を取る
原価は商品テーブルにしかありません。売上の各行から商品の原価を取るには：
```dax
原価合計 = SUMX(売上, 売上[数量] * RELATED(商品[原価]))
```
| 注文 | 商品ID | 数量 | RELATED(商品[原価]) | 数量×原価 |
|---|---|---|---|---|
| 1 | P01 | 2 | 800 | 1600 |
| 2 | P05 | 10 | 200 | 2000 |
- RELATED は **多側（売上）→ 1側（商品）** の向きで使う
- **行コンテキストの中（計算列、SUMX などの中）でだけ** 使える

### 4. 計算列でも RELATED
```dax
カテゴリ = RELATED(商品[カテゴリ])      // 売上テーブルの計算列
```
売上の各行に、その商品のカテゴリが入ります。

### 5. 仲間の関数（X 関数）
AVERAGEX・MINX・MAXX・COUNTX も、「1行ずつ計算してから、平均・最小・最大・個数」です。

@pitfalls
- **SUM(列) * SUM(列)** で金額を出す → 足してから掛けるので間違い。SUMX
- **SUMX の1つ目に列を渡す** `SUMX(売上[数量], …)` → テーブル（売上）を渡す
- **RELATED を使わずに 商品[原価]** → 「別のテーブルの列です。RELATED を使います」エラー
- **RELATED をメジャーでそのまま使う** → 行コンテキストがないのでエラー。SUMX の中で使う

@steps bi5a
1. 「行ごとに 数量×単価 を計算して合計」なので SUMX を使う
2. 1つ目の引数は回るテーブル（売上）、2つ目は1行分の計算式（売上[数量] * 売上[単価]）
3. 確定して、売上金額（金額列の合計）と同じ値になることを確認して採点

@steps bi5b
1. 1行分の計算は「数量 × その商品の原価」
2. 原価は商品テーブルにあるので RELATED(商品[原価]) で取る
3. SUMX(売上, …) の2つ目の引数に入れて確定・採点

@steps bi5c
1. 計算列なので行コンテキストがあり、RELATED がそのまま使える
2. RELATED(商品[カテゴリ]) で、その行の商品のカテゴリを取る
3. 「列を追加」してテーブルタブで確認して採点

@@lesson bi6
@image
「粗利率」「達成率」「構成比」など、ビジネスの指標の多くは **割り算** です。

DAX の割り算には **DIVIDE** を使うのが定石です。売上が0の月があっても、エラーや「∞」にならず、空白を返してくれる **安全装置付きの割り算** だからです。

もう1つ、式が長くなってきたら **VAR（変数）** を使いましょう。途中の計算結果に名前を付けておけるので、式が読みやすくなり、計算も速くなります。

@detail
### 1. / と DIVIDE の違い
| 式 | 分母が 0 のとき |
|---|---|
| `[粗利] / [売上金額]` | ∞ や NaN（グラフが崩れる） |
| `DIVIDE([粗利], [売上金額])` | **空白**（表示されない） |
| `DIVIDE([粗利], [売上金額], 0)` | 0（3つ目の引数＝代わりの値） |

### 2. 粗利 → 粗利率
```dax
粗利 = [売上金額] - [原価合計]
粗利率 = DIVIDE([粗利], [売上金額])
```
| カテゴリ | 売上金額 | 粗利 | 粗利率 |
|---|---|---|---|
| ドリンク | 236,730 | 118,030 | 49.9% |
| 文具 | 108,420 | 65,050 | 60.0% |
| 菓子 | 190,224 | 105,904 | 55.7% |
| **合計** | 589,254 | 319,364 | **54.2%** |
合計行の 54.2% は、各行の比率の平均ではなく、**合計の粗利 ÷ 合計の売上** です。メジャーは合計行でも「条件なし」で計算し直すので、比率が正しくなります。

### 3. VAR / RETURN
```dax
粗利率 =
VAR s = [売上金額]
VAR c = [原価合計]
RETURN
    DIVIDE(s - c, s)
```
- `VAR 名前 = 式` で途中の結果に名前を付ける（何個でも書ける）
- `RETURN` の後に、最終的に返す式
- [売上金額] を2回使っているが、VAR にしたので **計算は1回** で済む

### 4. VAR は「その時点で1回だけ」計算される
VAR の値は、定義した場所の条件で計算され、その後は固定の値です。後から CALCULATE で条件を変えても VAR の値は変わりません（第7回以降で効いてくる注意点）。

### 5. 1人あたり・1件あたり
```dax
顧客単価 = DIVIDE([売上金額], DISTINCTCOUNT(売上[顧客ID]))
```
分母にメジャーでなく関数を直接書いても OK です。

@pitfalls
- **/ で割る** → 0 除算で ∞ やエラー。DIVIDE
- **VAR の後に RETURN を忘れる** → 構文エラー
- **比率を合計行で平均と思う** → メジャーの合計行は全体で計算し直した値
- **表示形式** 比率はメジャーの書式を「パーセント」に（このアプリでは自動で % 表示）

@steps bi6a
1. 既にある [売上金額] と [原価合計] を使う
2. 粗利 ＝ 売上金額 − 原価合計。メジャー同士の引き算をそのまま書く
3. 確定して採点

@steps bi6b
1. VAR で売上金額を s、原価合計を c という名前にする（2行）
2. RETURN の後に DIVIDE(s - c, s)
3. 確定して、合計行が 54.2% になることを確認して採点

@steps bi6c
1. 分子は [売上金額]、分母は購入顧客数（売上[顧客ID] の重複なしの数）
2. 分母は DISTINCTCOUNT(売上[顧客ID]) をそのまま書ける
3. DIVIDE(分子, 分母) にして確定・採点

@@lesson bi7
@image
**CALCULATE** は DAX でいちばん重要な関数です。役割は **「条件を変えて計算する」** こと。

マトリックスの各セルには、行や列から自動的に条件（フィルターコンテキスト）がかかっていました。CALCULATE を使うと、その条件に **自分で条件を追加したり、上書きしたり** できます。

「菓子だけの売上」「東京の法人だけの売上」「いつ見ても2025年の売上」 ── こうした **条件付きの集計** はすべて CALCULATE で作ります。Excel の SUMIFS の強化版と考えると入りやすいです。

@detail
### 1. 形
```dax
菓子の売上 = CALCULATE([売上金額], 商品[カテゴリ] = "菓子")
```
- 1つ目：計算する式（メジャー）
- 2つ目以降：**条件（フィルター引数）**

### 2. 行が「地域」のマトリックスでの動き
| 地域 | 売上金額 | 菓子の売上 |
|---|---|---|
| 名古屋 | 76,782 | 26,322 |
| 大阪 | 165,579 | 39,330 |
| 東京 | 193,636 | 74,235 |
「名古屋」のセルでは：
1. もともとの条件：地域＝名古屋
2. CALCULATE が条件を追加：カテゴリ＝菓子
3. 「名古屋 **かつ** 菓子」の売上を計算 → 26,322

### 3. 同じ列の条件は「上書き」される（重要）
行が **カテゴリ** のマトリックスに「菓子の売上」を置くと：
| カテゴリ | 売上金額 | 菓子の売上 |
|---|---|---|
| ドリンク | 236,730 | **190,224** |
| 文具 | 108,420 | **190,224** |
| 菓子 | 190,224 | **190,224** |
どの行も菓子の売上になります。「ドリンク」の行の条件（カテゴリ＝ドリンク）が、CALCULATE の条件（カテゴリ＝菓子）で **上書き** されるからです。

| 状況 | 結果 |
|---|---|
| 行の条件と **別の列** の条件（地域の行 × カテゴリ条件） | 両方かかる（AND） |
| 行の条件と **同じ列** の条件（カテゴリの行 × カテゴリ条件） | CALCULATE の条件で上書き |

### 4. 複数の条件
```dax
東京法人売上 = CALCULATE([売上金額], 顧客[地域] = "東京", 顧客[区分] = "法人")
```
条件を `,` で並べると **すべて満たす（AND）**。

### 5. 数値・複数の値
```dax
2025年売上 = CALCULATE([売上金額], カレンダー[年] = 2025)               // 数値は " " なし
食品売上   = CALCULATE([売上金額], 商品[カテゴリ] IN {"菓子", "ドリンク"})  // どれか（OR）
```
列に「年」を置いても、`2025年売上` はどの年の列でも2025年の値になります（年の条件が上書きされるため）。

### 6. 1つの条件に書けるのは1つのテーブルの列だけ
`顧客[地域] = "東京" && 商品[カテゴリ] = "菓子"` は書けません。別々の引数にします。

@pitfalls
- **数値を " " で囲む** `カレンダー[年] = "2025"` → 数値とテキストは比べられない
- **条件の中でメジャーを使う** `CALCULATE([売上金額], [売上金額] > 1000)` → エラー。FILTER を使う（第9回）
- **2つのテーブルの条件を && でつなぐ** → 1つの条件に1つのテーブル。, で分ける
- **上書きに驚く** 同じ列の条件は置き換わる。行の条件を残して絞りたいなら KEEPFILTERS

@steps bi7a
1. 計算するのは [売上金額]
2. 条件は「商品のカテゴリが菓子」→ 商品[カテゴリ] = "菓子"
3. CALCULATE([売上金額], 条件) の形で確定。地域ごとに菓子の売上が出ることを確認して採点

@steps bi7b
1. 条件は2つ：顧客[地域] = "東京"、顧客[区分] = "法人"
2. CALCULATE の2つ目・3つ目の引数として , で並べる
3. 確定して採点

@steps bi7c
1. 条件は「カレンダーの年が 2025」。数値なので " " は付けない
2. CALCULATE([売上金額], カレンダー[年] = 2025)
3. 確定して、2026 の列にも 2025 年の値が出る（上書きされる）ことを確認して採点

@steps bi7d
1. 「菓子 または ドリンク」は IN と { } で書ける
2. 条件は 商品[カテゴリ] IN {"菓子", "ドリンク"}
3. CALCULATE に入れて確定・採点

@@lesson bi8
@image
「全体のうち何%？」という **構成比** は、レポートで最もよく使う指標の1つです。

構成比 ＝ その行の売上 ÷ **全体の売上**。分子は普通に計算できますが、問題は分母です。「ドリンク」の行では、すでに「カテゴリ＝ドリンク」の条件がかかっているので、普通に計算すると分母もドリンクの売上になってしまいます。

そこで **ALL** を使って、**かかっている条件を外し** ます。いわば「いったん眼鏡を外して全体を見る」関数です。

@detail
### 1. ALL で条件を外す
```dax
全体売上 = CALCULATE([売上金額], ALL(商品))
```
| カテゴリ | 売上金額 | 全体売上 |
|---|---|---|
| ドリンク | 236,730 | 589,254 |
| 文具 | 108,420 | 589,254 |
| 菓子 | 190,224 | 589,254 |
ALL(商品) は「商品テーブルにかかっている条件（カテゴリ＝ドリンクなど）を全部外す」という意味。どの行でも全体の売上になります。

### 2. 構成比
```dax
構成比 = DIVIDE([売上金額], CALCULATE([売上金額], ALL(商品)))
```
| カテゴリ | 構成比 |
|---|---|
| ドリンク | 40.2% |
| 文具 | 18.4% |
| 菓子 | 32.3% |
| 雑貨 | 9.1% |
| **合計** | **100.0%** |

### 3. 外す範囲を選ぶ
| 書き方 | 外れる条件 |
|---|---|
| `ALL(商品)` | 商品テーブルのすべての列 |
| `ALL(商品[カテゴリ])` | カテゴリ列の条件だけ |
| `ALLEXCEPT(商品, 商品[カテゴリ])` | 商品テーブルの、カテゴリ **以外** の条件 |
| `REMOVEFILTERS(…)` | ALL と同じ（「外す」意図が分かりやすい名前） |

### 4. カテゴリの中での構成比（ALLEXCEPT）
行が **商品名** のとき、「クッキーは菓子全体の何%？」を出したい。
- 「商品名＝クッキー」の条件は外したい
- でも「菓子」の範囲は残したい
```dax
カテゴリ内構成比 = DIVIDE([売上金額], CALCULATE([売上金額], ALLEXCEPT(商品, 商品[カテゴリ])))
```
クッキーの行では、分母 ＝ 商品の条件を外し、カテゴリ（菓子）だけ残した売上 ＝ 菓子全体の売上。

### 5. 年の中での地域構成比
行が地域、列が年のマトリックスで「各年の中で、各地域が何%か」。
- 外したいのは **地域の条件だけ**
- 年の条件は残す
```dax
地域構成比 = DIVIDE([売上金額], CALCULATE([売上金額], ALL(顧客[地域])))
```
ALL(顧客) でも地域は外れますが、ALL(顧客[地域]) にしておけば「地域だけ」と意図がはっきりします。

### 6. ALLSELECTED（参考）
スライサーで「東京・大阪」を選んでいるとき、その2地域の中での構成比を出したいなら ALLSELECTED。スライサーの選択は残し、表の行の条件だけを外します。

@pitfalls
- **ALL を忘れる** → 分母もその行の売上になり、全部 100%
- **ALL(売上) で外しすぎる** → 売上を通じたすべての条件（年・地域など）も外れる
- **外す範囲の取り違え** 「何の中での構成比か」を言葉にしてから、外す列を決める
- **表示形式** 構成比はパーセント表示に

@steps bi8a
1. 分子は [売上金額]
2. 分母は「商品の条件を全部外した売上」→ CALCULATE([売上金額], ALL(商品))
3. DIVIDE(分子, 分母) で確定し、合計行が 100% になることを確認して採点

@steps bi8b
1. 行は商品名。外したいのは商品の条件、残したいのはカテゴリ
2. 分母は CALCULATE([売上金額], ALLEXCEPT(商品, 商品[カテゴリ]))
3. DIVIDE で割って確定。同じカテゴリの商品を足すと 100% になるか確かめて採点

@steps bi8c
1. 外したいのは地域の条件だけ（年は残す）
2. 分母は CALCULATE([売上金額], ALL(顧客[地域]))
3. DIVIDE で割って確定。各年の列で合計が 100% になることを確認して採点
