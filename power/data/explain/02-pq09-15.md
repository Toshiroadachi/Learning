@@lesson pq9
@image
Excel でよく見る「店舗 × 4月・5月・6月」の表は、**人が読むための形（横持ち）** です。一方、ピボットテーブルや Power BI が得意なのは、**1行に1つの事実を書いた形（縦持ち）** です。

横持ちを縦持ちに直すのが **ピボット解除**。たとえるなら、**カレンダー形式の予定表を、1件ずつの予定リストに書き直す** 作業です。リストにしておけば、「月別」「店舗別」「四半期別」…どんな切り口の集計も自由にできます。

@detail
### 1. ビフォー・アフター
横持ち（元の表）：
| 店舗 | 4月 | 5月 | 6月 |
|---|---|---|---|
| 新宿店 | 1200 | 1350 | 1100 |
| 栄店 | 760 | null | 820 |

縦持ち（ピボット解除後）：
| 店舗 | 属性 | 値 |
|---|---|---|
| 新宿店 | 4月 | 1200 |
| 新宿店 | 5月 | 1350 |
| 新宿店 | 6月 | 1100 |
| 栄店 | 4月 | 760 |
| 栄店 | 6月 | 820 |
- 列見出しだった「4月・5月・6月」が **属性** 列の値に
- セルの数字が **値** 列に
- 栄店の5月（null）は行にならない

### 2. 「その他の列のピボット解除」を使う理由
**残したい列（店舗）を選んで**「その他の列のピボット解除」。
```powerquery
= Table.UnpivotOtherColumns(ソース, {"店舗"}, "属性", "値")
```
式には「店舗」しか書かれていません。来月「7月」列が増えても、**店舗以外は全部**解除の対象なので自動で含まれます。逆に「4月〜6月を選んでピボット解除」すると、式に 4月・5月・6月 が固定で書かれ、7月が漏れます。

### 3. 名前を整える
「属性」→「月」、「値」→「売上」に名前を変更して完成です。

### 4. 逆の操作：ピボット列（縦持ち → 横持ち）
経費データ（1行1申請）から「部署 × 費目」のクロス集計表を作ります。
1. まず **部署・費目・金額 以外の列を削除**（申請ID・申請日が残っていると、1行ずつバラバラのままになる）
2. 費目 列を選んで「ピボット列」→ 値列＝金額、集計＝合計

| 部署 | 費目 | 金額 | → | 部署 | 交通費 | 接待交際費 | 消耗品費 | 書籍代 |
|---|---|---|---|---|---|---|---|---|
| 営業部 | 交通費 | 1280 | | 営業部 | 5440 | 15000 | null | null |
| 営業部 | 接待交際費 | 15000 | | 総務部 | null | 22000 | 4180 | null |
| 営業部 | 交通費 | 860 | | 開発部 | 2400 | null | 6500 | 4800 |
```powerquery
= Table.Pivot(#"削除された他の列", List.Distinct(#"削除された他の列"[費目]), "費目", "金額", List.Sum)
```
- `List.Distinct(…[費目])` ＝ 費目の値の一覧（重複なし）が新しい列見出しになる
- `List.Sum` ＝ 同じ部署・費目が複数あれば合計する

> 集計表は「見せる」最後の段階で作るもの。分析の途中のデータは縦持ちのまま持っておきましょう。

@pitfalls
- **月の列を選んでピボット解除** → 新しい月が漏れる。残す列を選んで「その他の列」
- **属性・値の名前変更を忘れる** → 後で何の列か分からなくなる
- **ピボットの前に余分な列を残す** → 行がまとまらない
- **ピボットで集計関数を指定しない** → 同じ組み合わせが複数あると Error

@steps pq9a
1. 店舗の列見出しをタップ（店舗だけを選ぶ）
2. 変換 タブ →「その他の列のピボット解除」
3. 「属性」を「月」、「値」を「売上」に名前変更
4. 11行（栄店5月の空欄がない）になったか確認して採点

@steps pq9b
1. 部署・費目・金額の3列を選び、ホーム →「他の列の削除」
2. 費目の列見出しを選び、変換 →「ピボット列」
3. 値列「金額」、集計関数「合計」で OK
4. 部署が3行、費目が列見出しになったか確認して採点

@@lesson pq10
@image
グループ化は **「同じ種類のものを箱に分けて、箱ごとに数える」** 作業です。

経費の明細を部署ごとの箱に分け、それぞれの箱の中で「金額を合計する」「何件あるか数える」── Excel のピボットテーブルや SUMIF / COUNTIF でやっていることを、クエリの中で行います。クエリの中で集計しておけば、元データが増えても更新ボタン1つで集計表も最新になります。

@detail
### 1. ビフォー・アフター
明細（10行）：
| 部署 | 費目 | 金額 |
|---|---|---|
| 営業部 | 交通費 | 1280 |
| 営業部 | 接待交際費 | 15000 |
| 総務部 | 消耗品費 | 3200 |
| … | … | … |
部署でグループ化（合計金額・件数）：
| 部署 | 合計金額 | 件数 |
|---|---|---|
| 営業部 | 20440 | 4 |
| 総務部 | 26180 | 3 |
| 開発部 | 13700 | 3 |

### 2. 式の読み方
```powerquery
= Table.Group(ソース, {"部署"}, {
    {"合計金額", each List.Sum([金額]), type number},
    {"件数", each Table.RowCount(_), Int64.Type}
})
```
| 部分 | 意味 |
|---|---|
| `{"部署"}` | 何でグループ（箱）に分けるか |
| `"合計金額"` | 作る列の名前 |
| `each List.Sum([金額])` | 箱ごとに、金額を合計する |
| `each Table.RowCount(_)` | 箱ごとに、行数を数える |
ここでの `_` は **「その箱に入った行だけの表」**、`[金額]` は **「その箱の金額の一覧（リスト）」** です。

営業部の箱の中身：
| 部署 | 費目 | 金額 |
|---|---|---|
| 営業部 | 交通費 | 1280 |
| 営業部 | 接待交際費 | 15000 |
| 営業部 | 交通費 | 860 |
| 営業部 | 交通費 | 3300 |
→ `[金額]` は {1280, 15000, 860, 3300}、List.Sum で 20440、行数は 4。

### 3. 集計の種類（ダイアログの「操作」）
| 操作 | 式 |
|---|---|
| 合計 / 平均 / 最大 / 最小 | List.Sum / List.Average / List.Max / List.Min |
| 行数のカウント | Table.RowCount(_) |
| 個別の行数のカウント | 重複を除いた件数 |

### 4. 複数の列でグループ化
「部署 × 費目」ごとの合計は、グループ化する列を2つにします。
```powerquery
= Table.Group(ソース, {"部署", "費目"}, {{"合計", each List.Sum([金額]), type number}})
```
| 部署 | 費目 | 合計 |
|---|---|---|
| 営業部 | 交通費 | 5440 |
| 営業部 | 接待交際費 | 15000 |
| 総務部 | 消耗品費 | 4180 |

### 5. 集計する列がなければ先に作る
売上明細には「金額」列がないので、**カスタム列で 数量×単価 を作ってから**グループ化します。最後に並べ替えればランキングになります。

> グループ化の結果は、グループ化に使った列と集計列**だけ**になります（他の列は消える）。

@pitfalls
- **「行数のカウント」と「合計」の取り違え** 件数は Table.RowCount、金額の合計は List.Sum
- **集計列がまだない** → 先にカスタム列で作る
- **グループ化の後に元の列を使おうとする** → もう存在しない
- **並び順** グループは最初に出てきた順。ランキングにするなら並べ替えを追加

@steps pq10a
1. ホーム →「グループ化」
2. グループ化する列に「部署」を選ぶ
3. 1つ目の集計：列名「合計金額」、操作「合計」、列「金額」
4. 「＋ 集計の追加」で2つ目：列名「件数」、操作「行数のカウント」→ OK
5. 3行・3列になったか確認して採点

@steps pq10b
1. 列の追加 →「カスタム列」で「金額」＝ `[数量] * [単価]`
2. ホーム →「グループ化」→ グループ化する列「カテゴリ」、列名「売上金額」、操作「合計」、列「金額」
3. 売上金額の列見出し →「降順で並べ替え」
4. ドリンクが一番上になったか確認して採点

@steps pq10c
1. ホーム →「グループ化」
2. グループ化する列で「部署」と「費目」の両方を選ぶ（複数選択）
3. 列名「合計」、操作「合計」、列「金額」→ OK
4. 7行・3列になったか確認して採点

@@lesson pq11
@image
マージは **「VLOOKUP の上位版」** です。

受注データには商品IDしか書いていない。商品名や単価は商品マスタにある ── このとき Excel では VLOOKUP で1列ずつ持ってきますが、パワークエリの「クエリのマージ」なら、**キー（商品ID）で2つの表を突き合わせて、必要な列をまとめて持ってこられます**。

さらに、「マスタに登録されていない商品はどれ？」のような **突き合わせのチェック** も、結合の種類を変えるだけでできます。

@detail
### 1. 2つの表
受注データ：
| 受注ID | 商品ID | 数量 |
|---|---|---|
| 501 | P01 | 2 |
| 502 | P05 | 12 |
| 504 | P09 | 10 |
商品マスタ：
| 商品ID | 商品名 | 標準単価 |
|---|---|---|
| P01 | コーヒー豆 | 1500 |
| P05 | クッキー | 450 |
（P09 はマスタにない）

### 2. マージの手順
1. 受注データのクエリで ホーム →「クエリのマージ」
2. 相手のテーブル＝商品マスタ
3. 両方の **キーの列**（商品ID）を選ぶ
4. 結合の種類を選ぶ → OK
5. 右端に「商品マスタ」という列ができ、中身は **Table（入れ子の表）**
6. その列見出しの「展開」で、取り出す列を選ぶ

```powerquery
#"マージされたクエリ数" = Table.NestedJoin(ソース, {"商品ID"}, 商品マスタ, {"商品ID"}, "商品マスタ", JoinKind.LeftOuter),
#"展開された 商品マスタ" = Table.ExpandTableColumn(#"マージされたクエリ数", "商品マスタ", {"商品名", "標準単価"}, {"商品名", "標準単価"})
```
展開後：
| 受注ID | 商品ID | 数量 | 商品名 | 標準単価 |
|---|---|---|---|---|
| 501 | P01 | 2 | コーヒー豆 | 1500 |
| 502 | P05 | 12 | クッキー | 450 |
| 504 | P09 | 10 | null | null |
P09 はマスタにないので null（VLOOKUP の #N/A にあたる）。

### 3. 結合の種類で残る行が変わる
| 種類 | 上の例で残る受注 | 使いどころ |
|---|---|---|
| 左外部（既定） | 501・502・504（全部） | VLOOKUP と同じ |
| 内部 | 501・502 | マスタにあるものだけ |
| 左反 | **504 だけ** | マスタ未登録のチェック |
| 完全外部 | 全部＋マスタだけにある商品も | 2つのリストの突き合わせ |

### 4. 展開時のプレフィックス
「元の列名をプレフィックスとして使用します」にチェックが入っていると、列名が「商品マスタ.商品名」になります。不要ならチェックを外します。

### 5. マージ後の計算
展開した標準単価を使って、カスタム列で `[数量] * [標準単価]` を作れば金額が出ます。内部結合にしておくと、単価が null の行が出ないので計算がきれいになります。

### 6. キーの型をそろえる
片方の商品IDがテキスト「1」、もう片方が整数 1 だと一致しません。マージ前に両方の型をそろえましょう。

@pitfalls
- **キーの列を選び忘れる・違う列を選ぶ** → すべて null になる
- **型や表記ゆれ（空白・大文字小文字）でキーが一致しない**
- **展開でプレフィックスのチェックを外し忘れる** → 列名が「商品マスタ.商品名」に
- **一致が複数あると行が増える** マスタ側のキーに重複がないか注意
- **左反の後、入れ子の列が残る** → 不要なら列の削除

@steps pq11a
1. ホーム →「クエリのマージ」→ マージするテーブル「商品マスタ」
2. 受注データのキー・相手のキーとも「商品ID」、結合の種類「左外部」→ OK
3. 右端の「商品マスタ」列の見出し →「↔ 展開」
4. 「商品名」と「標準単価」だけにチェック、「元の列名をプレフィックスとして使用します」のチェックを外して OK
5. P09 の行が null になっているか確認して採点

@steps pq11b
1. ホーム →「クエリのマージ」→ 商品マスタ、キーは両方「商品ID」
2. 結合の種類を「左反（最初の行のみ）」にして OK
3. できた「商品マスタ」列の見出し →「列の削除」
4. 受注504（P09）の1行だけになったか確認して採点

@steps pq11c
1. ホーム →「クエリのマージ」→ 商品マスタ、キーは「商品ID」、結合の種類「内部」
2. 「商品マスタ」列を展開 →「標準単価」だけ、プレフィックスなし
3. 列の追加 →「カスタム列」で「金額」＝ `[数量] * [標準単価]`
4. 6行（P09 なし）で金額があるか確認して採点

@@lesson pq12
@image
マージが「**横に**つなぐ（列を足す）」なら、追加は「**縦に**つなぐ（行を足す）」です。

東京支店・大阪支店から同じ形の売上表が届くとき、2つを1つの表に積み重ねれば、全社の集計ができます。さらに **フォルダーから取り込み** を使えば、「毎月フォルダーにファイルを入れて更新するだけ」で、何十個のファイルでも自動で1つの表になります。これが実務でいちばん効く使い方です。

@detail
### 1. クエリの追加
東京支店：
| 日付 | 商品 | 金額 |
|---|---|---|
| 2026/06/01 | コーヒー豆 | 4500 |
| 2026/06/02 | クッキー | 2700 |
| 2026/06/03 | ノート | 3300 |
大阪支店：
| 日付 | 商品 | 金額 |
|---|---|---|
| 2026/06/01 | 緑茶ボトル | 3600 |
| 2026/06/04 | マグカップ | 2400 |
ホーム →「クエリの追加」→ 大阪支店：
```powerquery
= Table.Combine({ソース, 大阪支店})
```
→ 5行の表（東京の3行の下に大阪の2行）。`{ }` の中に表をいくつ並べてもつなげられます。

### 2. 列は「名前」で対応する
| 東京の列 | 大阪の列 | 結果 |
|---|---|---|
| 日付・商品・金額 | 日付・商品・金額 | きれいに3列 |
| 日付・商品・金額 | 日付・商品・**売上金額** | 4列になり、それぞれ null が入る |
列の**順番**が違っても名前が同じなら問題ありませんが、**名前**が違うと別の列になります。つなぐ前に名前をそろえましょう。

### 3. どの支店のデータか分かるようにする
つないだ後だと、どの行がどの支店か分かりません。**つなぐ前に**、それぞれに「支店」列を付けます。
```powerquery
#"追加されたカスタム" = Table.AddColumn(ソース, "支店", each "東京"),
#"追加されたクエリ" = Table.Combine({#"追加されたカスタム", Table.AddColumn(大阪支店, "支店", each "大阪")})
```
`each "東京"` は「どの行にも同じ値 "東京" を入れる」という意味です。2行目では、大阪支店の表に支店列を付けたものを、その場で作って Combine に渡しています。
| 日付 | 商品 | 金額 | 支店 |
|---|---|---|---|
| 2026/06/01 | コーヒー豆 | 4500 | 東京 |
| … | … | … | … |
| 2026/06/04 | マグカップ | 2400 | 大阪 |

### 4. フォルダーから取り込み（PC で使う最強パターン）
1. データ → データの取得 → ファイルから → **フォルダーから**
2. 「結合」→「データの結合と変換」→ サンプルファイルを1つ選ぶ
3. サンプルに対して整形すると、同じ整形が**全ファイルに**適用されて縦につながる
4. 新しいファイルをフォルダーに入れて **更新** するだけで行が増える
自動で「Source.Name」列（ファイル名）が付くので、ファイル名から年月や支店名を取り出せば、手順3の「支店」列も自動で作れます。

@pitfalls
- **列名の表記ゆれ** 「金額」「売上金額」は別の列になる
- **支店列を付けずにつなぐ** → どの行がどこのデータか分からなくなる
- **フォルダーに不要なファイルが混ざる** （一時ファイル ~$… など）→ Name 列でフィルター
- **ヘッダー行が各ファイルにある CSV** フォルダーからの結合では自動で処理されるが、手でつなぐときは注意

@steps pq12a
1. ホーム →「クエリの追加」
2. 追加するテーブル「大阪支店」→ OK
3. 5行になったか確認して採点

@steps pq12b
1. ホーム →「詳細エディター」を開く
2. ソースの後に、東京の表へ「支店」列（値は "東京"）を追加するステップを書く
3. 次のステップで、そのステップと「大阪支店に支店列（"大阪"）を追加した表」を Table.Combine の { } に並べる
4. in の後を最後のステップ名にして完了 → 4列・5行になったか確認して採点

@@lesson pq13
@image
これまでボタンで作ってきたステップは、すべて **M 言語** という言葉で書かれていました。**詳細エディター**を開くと、それが1つの「レシピ」として読めます。

M 言語が読めると、
- 他の人が作ったクエリが何をしているか分かる
- ボタンにない細かい処理を書ける
- ネットや AI に教わった式を貼り付けて使える

ようになります。全部覚える必要はありません。**「let の中にステップが並び、in の後が結果」** という骨組みと、**each [列名]** が読めれば十分なスタートです。

@detail
### 1. クエリの骨組み
```powerquery
let
    ソース = Excel.CurrentWorkbook(){[Name="売上明細"]}[Content],
    #"フィルターされた行" = Table.SelectRows(ソース, each [担当者] = "田中"),
    #"追加されたカスタム" = Table.AddColumn(#"フィルターされた行", "金額", each [数量] * [単価])
in
    #"追加されたカスタム"
```
| 部分 | 意味 |
|---|---|
| `let` | ここからステップを並べます |
| `名前 = 式` | 1つのステップ。「適用したステップ」の1行にあたる |
| `,`（カンマ） | ステップの区切り。**最後のステップの後には付けない** |
| `in` | ここから結果 |
| `#"追加されたカスタム"` | 結果として返すステップ |
- 空白や記号を含む名前は `#"…"` で囲む（`ソース` のような普通の名前はそのまま）
- 各ステップは、1つ前のステップの名前を最初の引数にしてつながっている

### 2. each と [列名] の正体
`each [数量] * [単価]` は、「**1行を受け取って、その行の 数量 × 単価 を返す小さな関数**」です。
```powerquery
each [数量] * [単価]
(_) => _[数量] * _[単価]     // まったく同じ意味の書き方
```
Table.AddColumn や Table.SelectRows は、この関数を**全部の行に1回ずつ**実行してくれます。

### 3. 値の種類
| 種類 | 書き方 | 例 |
|---|---|---|
| テキスト | "…" | "東京" |
| 数値 | そのまま | 1500 |
| 日付 | #date(年,月,日) | #date(2026, 4, 1) |
| リスト | { } | {"日付", "金額"}、{1..10} |
| レコード（1行） | [名前=値, …] | [Name="売上明細"] |
| テーブル | 行と列 | ソース |
`Excel.CurrentWorkbook(){[Name="売上明細"]}[Content]` は、「ブックのテーブル一覧から、Name が売上明細の行を取り出し、その Content（中身の表）を取る」と読みます。

### 4. CSV ファイルから読み込む
```powerquery
ソース = Csv.Document(File.Contents("C:\データ\売上_2026年6月.csv"), [Delimiter=",", Encoding=65001]),
#"昇格されたヘッダー数" = Table.PromoteHeaders(ソース, [PromoteAllScalars=true]),
#"変更された型" = Table.TransformColumnTypes(#"昇格されたヘッダー数", {{"金額", Int64.Type}})
```
CSV は読み込んだ直後は Column1, Column2… なので、ヘッダーの昇格 → 型の変更 が定番の流れです。

### 5. 自分で関数を作る
```powerquery
税込 = (金額 as number) as number => Number.Round(金額 * 1.1),
#"追加されたカスタム" = Table.AddColumn(ソース, "税込金額", each 税込([数量] * [単価]))
```
`(引数) => 式` で関数を作り、ステップ名（税込）で呼び出せます。同じ計算を何度も使うときに便利です。

### 6. エラーメッセージの読み方
| メッセージ | よくある原因 |
|---|---|
| 名前 '○○' は認識されませんでした | 関数名・ステップ名のつづり、大文字小文字 |
| 列 '○○' が見つかりませんでした | 列名の打ち間違い、前のステップで削除済み |
| 「,」が必要です / Token Comma expected | ステップの間のカンマ忘れ |
| 式の後ろに余分な文字 | 最後のステップの後に余分なカンマ |

@pitfalls
- **最後のステップの後にカンマ** → 構文エラー
- **in の後のステップ名が違う** → 途中までの結果が返る
- **#"…" の付け忘れ** 空白や記号・日本語の文が入った名前は `#"…"`
- **関数名の大文字小文字** `Table.SelectRows`（`table.selectrows` はエラー）
- **CSV でヘッダーを昇格せずに型変更** → 見出しの文字が Error になる

4. 最後に 日付・商品名・金額 を残す Table.SelectColumns のステップ。各ステップの最初の引数は1つ前のステップ名
5. in の後を最後のステップ名にして「完了」→ 採点

@steps pq13b

3. Table.TransformColumnTypes で数量・金額を Int64.Type に（他の列も型を付けて OK）
4. Table.Group で店舗ごとに金額を合計し、列名「売上」にする（`{{"売上", each List.Sum([金額]), type number}}`）
5. in の後を最後のステップ名にして採点

@@lesson pq14
@image
売上や経費の分析では、日付から **「年月」「四半期」「年度」** などの切り口を作る場面が必ず出てきます。

特に日本の会社では **4月始まりの年度** が多く、「2026年2月は2025年度」のような変換が必要です。Excel では毎回関数を書いていた作業を、クエリに1度書いておけば、毎月のデータに自動で適用されます。

@detail
### 1. 前提：日付型にする
日付の関数は **日付型の列** にしか使えません。まず列見出しの「型の変更」→「日付」（アイコンが 📅 に）。

### 2. 日付から部品を取り出す
| 欲しいもの | 式 | 2026/04/05 の結果 |
|---|---|---|
| 年 | Date.Year([日付]) | 2026 |
| 月 | Date.Month([日付]) | 4 |
| 四半期 | Date.QuarterOfYear([日付]) | 2 |
| 月の末日 | Date.EndOfMonth([日付]) | 2026/04/30 |
| 曜日名 | Date.DayOfWeekName([日付]) | 日曜日 |
列の追加 → 日付 のメニューからも作れます。

### 3. 「年月」の文字列を作る
```powerquery
each Date.ToText([日付], "yyyy-MM")
```
| 日付 | 年月 |
|---|---|
| 2026/04/01 | 2026-04 |
| 2026/05/13 | 2026-05 |
- 書式の **MM（大文字）が月**、mm（小文字）は「分」なので注意
- "yyyy-MM" のように **0埋めの2桁** にしておくと、文字の並べ替えでも 2026-04 → 2026-05 → … → 2026-12 と正しい順になる

年月を作ったら、グループ化で月ごとの合計が出せます。
| 年月 | 数量合計 |
|---|---|
| 2026-04 | 180 |
| 2026-05 | 68 |

### 4. 4月始まりの会計年度
「4月以降ならその年、1〜3月なら前の年」を if で書きます。
```powerquery
each if Date.Month([申請日]) >= 4 then Date.Year([申請日]) else Date.Year([申請日]) - 1
```
| 申請日 | 月 | 判定 | 会計年度 |
|---|---|---|---|
| 2026/04/03 | 4 | 4以上 → その年 | 2026 |
| 2026/02/10 | 2 | 4未満 → 前の年 | 2025 |
「FY2026」の形にするなら、数値を文字にしてからつなげます。
```powerquery
each "FY" & Text.From(if Date.Month([申請日]) >= 4 then Date.Year([申請日]) else Date.Year([申請日]) - 1)
```

### 5. 日数の計算
日付どうしを引き算すると「期間（Duration）」という値になります。日数の数値にするには Duration.Days。
```powerquery
each Duration.Days(#date(2026, 4, 1) - [入社日])
```
| 入社日 | 勤続日数（2026/4/1 時点） |
|---|---|
| 2024/04/01 | 730 |
| 2021/04/01 | 1826 |
`#date(2026, 4, 1)` は固定の日付。今日を基準にしたいときは `Date.From(DateTime.LocalNow())` を使います（PC で。更新した日によって結果が変わる）。

@pitfalls
- **日付型にしていない** → Date.Year などがエラー
- **"yyyy-mm"（小文字 mm）** → 「分」になってしまう
- **数値と文字を & でつなぐ** → エラー。Text.From で文字にする
- **日付の引き算をそのまま数値として使う** → 期間型なので Duration.Days が必要
- **会計年度の境目** 4月は「以上」（>= 4）

@steps pq14a
1. 日付の列見出し →「型の変更」→「日付」
2. 列の追加 →「カスタム列」で「年月」＝ `Date.ToText([日付], "yyyy-MM")`
3. ホーム →「グループ化」→ グループ化する列「年月」、列名「数量合計」、操作「合計」、列「数量」
4. 2026-04 と 2026-05 の2行になったか確認して採点

@steps pq14b
1. 申請日を「日付」型に変更
2. 列の追加 →「カスタム列」で「会計年度」
3. 式は "FY" & Text.From( 4月以降ならその年、そうでなければ前年 の if 式 )
4. 4月の申請が FY2026 になっているか確認して採点

@steps pq14c
1. 入社日を「日付」型に変更
2. 列の追加 →「カスタム列」で「勤続日数」
3. 式は `Duration.Days(#date(2026, 4, 1) - [入社日])`
4. E005（2024/4/1 入社）が 730 になっているか確認して採点

@@lesson pq15
@image
クエリを作ったら、次は **「どこに出すか」「どう更新するか」「人に渡しても動くか」** を考える段階です。

料理にたとえると、ここまでは「調理（整形）」。最後は「盛り付け（読み込み先）」と「作り置き・お裾分け（更新と共有）」です。せっかく作ったクエリも、自分の PC のファイルの場所に依存していると、同僚の PC では動きません。実務で困らないためのコツをまとめます。

@detail
### 1. 読み込み先の選び方
| 読み込み先 | 例 | 向いている場面 |
|---|---|---|
| テーブル | シートに表として出す | ふつうの集計・確認 |
| ピボットテーブル | すぐにクロス集計 | 縦持ちデータの分析 |
| 接続の作成のみ | シートに出さない | **マージ用のマスタ・途中のクエリ** |
| データモデルに追加 | Power Pivot | **100万行超**、複数の表をリレーションで |
シートは約104万行が上限です。それ以上のデータはデータモデルへ。

### 2. 更新のしくみ
- **データ → すべて更新**（Ctrl + Alt + F5）で、元データを読み直し、全ステップを再実行
- クエリのプロパティで「ファイルを開くときに更新」「○分ごとに更新」も設定できる
- 更新すると出力先の表は **丸ごと作り直される** → 表の外に手入力した列は、行がずれる危険あり

### 3. パラメーターでパスを1か所に
```powerquery
ソース = Csv.Document(File.Contents("C:\Users\自分\Desktop\売上.csv"))
```
このように個人の PC の場所が書いてあると、他の人の PC では「ファイルが見つかりません」になります。
- 共有フォルダー・SharePoint・OneDrive にデータを置く
- **ホーム → パラメーターの管理** で「フォルダーパス」を作り、ソースのパスをパラメーターに置き換える → 場所が変わっても1か所直すだけ

### 4. 速くするコツ
- 不要な列・行は **できるだけ早いステップで** 削除・フィルター（後のステップが扱うデータ量が減る）
- データベースから読むときは、フィルターなどが元のサーバー側で実行される（**クエリの折りたたみ**）。途中に複雑なカスタム列を挟むと、それ以降は PC 側で処理されて遅くなることがある
- 同じソースを何度も使うなら、元のクエリを右クリック →「参照」で分岐させる

### 5. 共有するときのチェックリスト
| チェック | 理由 |
|---|---|
| データの場所は共有の場所か | 個人のパスは他の人の PC にない |
| 補助クエリは「接続のみ」か | シートが散らからない |
| 資格情報 | パスワードはファイルに保存されない。開いた人がそれぞれ認証する |
| クエリの依存関係 | 表示 → クエリの依存関係 で、どのクエリが何を使っているか確認 |

### 6. Power BI でも同じ
Power BI Desktop の「データの変換」はパワークエリそのものです。Excel の詳細エディターの M をコピーして、Power BI の空のクエリに貼り付ければ移植できます。

@pitfalls
- **シートの表の横に手入力** → 更新で行がずれる。計算はテーブル内の列（Excel の計算列）に
- **個人のパスのまま共有** → 他の人の PC で更新エラー
- **マスタをテーブルで読み込む** → シートが増えて重くなる。接続のみで十分
- **最後にまとめてフィルター** → 遅い。早めに絞る
