@@lesson ap1
@image
Power Apps は **「Excel の数式を書く感覚で、スマホの業務アプリを作れる道具」** です。

紙の申請書、Excel で回している点検表、メールでやり取りしている報告 ── こうした業務を、ボタンや入力欄のある **アプリ** にできます。プログラミング言語を一から覚える必要はなく、画面に部品（ラベル・ボタン・入力欄・一覧）を置いて、**部品の設定欄に Excel のような数式を書く** だけです。

この数式の言葉を **Power Fx** と呼びます。

@detail
### 1. 画面は「部品（コントロール）」の組み合わせ
| 部品 | 役割 | 例 |
|---|---|---|
| ラベル（Label） | 文字を表示 | 「経費申請一覧」 |
| テキスト入力（TextInput） | 文字を入力 | 検索ボックス |
| ドロップダウン（Dropdown） | 選択肢から選ぶ | ステータス |
| ボタン（Button） | 押すと動作 | 承認する |
| ギャラリー（Gallery） | データの一覧 | 申請の一覧 |
| トグル（Toggle） | オン・オフ | 金額の大きい順 |

### 2. すべては「プロパティ ＝ 数式」
部品にはそれぞれ **プロパティ（設定項目）** があります。
| 部品 | プロパティ | 意味 | 数式の例 |
|---|---|---|---|
| ラベル | Text | 表示する文字 | `"こんにちは"` |
| ラベル | Color | 文字の色 | `Color.Red` |
| ボタン | OnSelect | 押したときの動作 | `Navigate(詳細画面)` |
| ギャラリー | Items | 表示するデータ | `経費申請` |
| 何でも | Visible | 表示するか | `true` / `false` |
Excel のセルに `=A1+B1` を書くように、プロパティに数式を書きます。

### 3. 文字をつなげる &
```powerfx
"ようこそ、" & User().FullName & " さん"
```
| 部分 | 意味 |
|---|---|
| `"ようこそ、"` | 文字はそのまま " " で囲む |
| `&` | つなげる（Excel と同じ） |
| `User().FullName` | 今アプリを使っている人の名前（このアプリでは「山田 太郎」） |
→ 表示：**ようこそ、山田 太郎 さん**

`User()` は関数で、`.FullName` はその結果から「氏名」を取り出す書き方です（ドット「.」で中身を取り出す）。

### 4. 数式は自動で再計算される
Excel で A1 を変えると、A1 を使っているセルが自動で変わるのと同じで、Power Apps でも **参照しているものが変わると表示が自動で更新** されます。「更新ボタン」のような処理を書く必要はありません。

### 5. このアプリの演習画面の見方
| 場所 | Studio での名前 | 役割 |
|---|---|---|
| スマホの枠 | キャンバス／プレビュー | 実際に入力・タップ・ボタン操作ができる |
| チップの並び | ツリー ビュー | 部品の一覧。タップで選択（└ はギャラリーの中の部品） |
| 2つのプルダウン | 部品とプロパティ | 「どの部品の、どのプロパティか」（✏ が演習で書く場所） |
| fx の下のエディター | 数式バー | 数式を書くと、少し待つとプレビューに反映 |
| 灰色の枠 | 結果の表示 | 今の数式の値（テーブルなら中身の一部） |

@pitfalls
- **文字を " " で囲み忘れる** `ようこそ` → 「名前が無効です」エラー
- **全角の " や ＆** → エラー。記号は半角
- **関数名の大文字小文字** `user()` ではなく `User()`
- **& の前後** 空白は表示に影響しない。表示したい空白は " " の中に入れる

@steps ap1a
1. 表示したい文は「ようこそ、」＋ユーザー名＋「 さん」
2. 固定の文字は " " で囲み、ユーザー名は `User().FullName`
3. 3つを & でつなぐ（「さん」の前の半角スペースは " さん" の中に入れる）
4. プレビューに「ようこそ、山田 太郎 さん」と出たら採点

@@lesson ap2
@image
Power Fx は Excel の数式とよく似ていますが、決定的な違いが1つあります。

Excel は **セル番地（A1、B2）** で値を参照しますが、Power Apps には セルがありません。代わりに **部品の名前.プロパティ** で参照します。「TextInput1 に入力された文字」は `TextInput1.Text`、「Dropdown1 で選ばれた値」は `Dropdown1.Selected.Value` です。

部品どうしが名前で結びつき、入力が変わるたびに表示が自動で変わる ── これがアプリの「動き」の正体です。

@detail
### 1. 部品の値を参照する
| 部品 | 値の取り出し方 | 中身の例 |
|---|---|---|
| テキスト入力 | `TextInput1.Text` | "交通"（文字） |
| ドロップダウン | `Dropdown1.Selected.Value` | "承認待ち" |
| トグル | `Toggle1.Value` | true / false |
| ギャラリー | `Gallery1.Selected.件名` | 選んだ行の件名 |

### 2. 入力をそのまま表示（連動）
Label1 の Text に：
```powerfx
"検索語: " & TextInput1.Text
```
| TextInput1 に入力 | Label1 の表示 |
|---|---|
| （空） | 検索語: |
| 交通 | 検索語: 交通 |
| 交通費 | 検索語: 交通費 |
入力するたびに、ラベルが自動で変わります（プレビューで試してみましょう）。

### 3. 文字 → 数値（Value）、数値 → 書式付きの文字（Text）
テキスト入力の中身は、数字を入力しても **文字** です。計算するときは `Value()` で数値にします。
```powerfx
Value(txt金額.Text) * 1.1
```
| 入力 | Value(…) | × 1.1 |
|---|---|---|
| "1000" | 1000 | 1100 |
| "2480" | 2480 | 2728 |

見やすく表示するときは `Text(値, 書式)`：
| 式 | 結果 |
|---|---|
| `Text(1100, "#,##0")` | "1,100" |
| `Text(2728, "¥#,##0")` | "¥2,728" |
| `Text(0.153, "0.0%")` | "15.3%" |
| `Text(Today(), "yyyy/mm/dd")` | "2026/06/15" |

### 4. 組み合わせ
```powerfx
"税込 " & Text(Value(txt金額.Text) * 1.1, "¥#,##0")
```
内側から読みます：① 入力を数値に → ② 1.1 倍 → ③ ¥ と桁区切りの文字に → ④ 前に「税込 」をつなげる。

### 5. 演算子のまとめ
| 記号 | 意味 |
|---|---|
| `&` | 文字をつなぐ |
| `+ - * /` | 計算 |
| `=` `<>` | 等しい・等しくない（= は1つ） |
| `< > <= >=` | 大小の比較 |
| `&&`（And）`||`（Or）`!`（Not） | かつ・または・否定 |
引数の区切りは `,`、複数の動作をつなぐのは `;`（第9回）。

@pitfalls
- **テキストを計算に使う** "1000" * 1.1 でも動くことがあるが、Value() で数値にするのが確実
- **文字の結合に +** → エラーや意図しない計算。& を使う
- **Text の書式** 円記号付きは "¥#,##0"、小数1桁は "0.0"
- **部品名のつづり** TextInput1 と textinput1 は別。ツリー ビューの名前をそのまま使う

@steps ap2a
1. 表示したいのは「検索語: 」＋入力された文字
2. 入力された文字は `TextInput1.Text`
3. 2つを & でつなぐ。プレビューの検索ボックスに文字を入れて、ラベルが変わることを確認してから採点

@steps ap2b
1. 入力された金額（文字）を `Value(txt金額.Text)` で数値にする
2. それに 1.1 を掛ける
3. `Text(…, "¥#,##0")` で ¥ と桁区切りの文字にする
4. 前に "税込 " を & でつなぐ。プレビューで金額を入力して確かめてから採点

@@lesson ap3

**ギャラリー**は、データの一覧を表示する部品です。スマホのメールアプリの受信トレイを思い浮かべてください。1通ごとに「差出人・件名・日時」が同じレイアウトで並んでいます。

ギャラリーも同じで、**1行分のレイアウト（テンプレート）を1回作るだけ** で、データの件数だけ自動でくり返し表示されます。テンプレートの中では **ThisItem**（この行）を使って、各行の値を表示します。

@detail
### 1. Items にデータを指定する
ギャラリーの Items プロパティに、データソース（表）の名前を書きます。
```powerfx
経費申請
```
→ 経費申請の10件が一覧で表示されます。

### 2. テンプレートと ThisItem
ギャラリーの中の部品（ツリーで └ が付いているもの）は、**1行ごとに** 計算されます。
| 部品 | Text の式 | 1行目の表示 | 2行目の表示 |
|---|---|---|---|
| Title1 | `ThisItem.件名` | 大阪出張 新幹線代 | 会議用お茶菓子 |
| Subtitle1 | `ThisItem.申請者` | 田中 誠 | 伊藤 恵 |
`ThisItem` は「今描いている行のデータ」、`.件名` はその行の件名列です。

### 3. 複数の列をつなげて表示
```powerfx
ThisItem.部署 & "・" & ThisItem.区分
```
| 行 | 表示 |
|---|---|
| 1 | 営業部・交通費 |
| 2 | 営業部・会議費 |
| 4 | 総務部・消耗品費 |

### 4. 選んでいる行（Selected）
ギャラリーの行をタップすると、その行が **選択中** になります。ギャラリーの **外** の部品からは：
```powerfx
Gallery1.Selected.件名
```
| タップした行 | Label1 の表示 |
|---|---|
| 1行目 | 大阪出張 新幹線代 |
| 4行目 | プリンタートナー |
「一覧で選んだ申請の詳細を、横や別の画面に表示する」のは、この Selected を使った定番の作り方です。

### 5. ThisItem と Selected の使い分け
| 書く場所 | 使うもの |
|---|---|
| ギャラリーの**中**の部品 | ThisItem（その行） |
| ギャラリーの**外**の部品 | Gallery1.Selected（選んでいる行） |

### 6. データソースの種類（PC で作るとき）
| データソース | 特徴 |
|---|---|
| SharePoint リスト | Microsoft 365 があれば追加費用なし。定番 |
| Excel（OneDrive） | 手軽。表は「テーブル」にしておく必要あり |
| Dataverse | Power Platform 専用のデータベース（プレミアム） |

@pitfalls
- **ギャラリーの外で ThisItem** → 「ThisItem はギャラリーの中だけ」エラー
- **Items に文字で書く** `"経費申請"` → ただの文字。データソース名は " " なし
- **列名のつづり** 件名・申請者 など、データの列名どおりに（ツリーで「変数・データ」を見ると確認できる）
- **Selected の後の列名を忘れる** `Gallery1.Selected` だけではレコード（1行全体）。`.件名` まで書く

@steps ap3a
1. 表示したいデータの名前は「経費申請」
2. Gallery1 の Items に、" " を付けずに 経費申請 と書く
3. プレビューに10件並んだら採点

@steps ap3b
1. Subtitle1 はギャラリーの中の部品なので、ThisItem でその行の値が取れる
2. 部署は ThisItem.部署、区分は ThisItem.区分
3. 間に全角の「・」を入れて & でつなぐ。各行が「営業部・交通費」の形になったら採点

@steps ap3c
1. Label1 はギャラリーの外にあるので、選択中の行は Gallery1.Selected
2. その件名なので Gallery1.Selected.件名
3. プレビューでギャラリーの別の行をタップし、ラベルが変わることを確認して採点

@@lesson ap4
@image
**Filter** は、一覧から **条件に合う行だけを残す** 関数です。パワークエリの行のフィルター、Excel のオートフィルターと同じ役割です。

業務アプリでは「承認待ちだけ見たい」「自分の申請だけ見たい」がとても多く、Filter は最もよく使う関数の1つです。さらにドロップダウンと組み合わせれば、**利用者が選んだ条件で一覧が切り替わる** 画面が作れます。

@detail
### 1. Filter の形
```powerfx
Filter(経費申請, ステータス = "承認待ち")
```
| 部分 | 意味 |
|---|---|
| 経費申請 | 絞り込むデータ |
| ステータス = "承認待ち" | 残す条件（各行について判定） |
条件の中では **列名をそのまま** 書けます（各行のステータス）。

ビフォー（10件）→ アフター（4件）：
| ID | 件名 | ステータス |
|---|---|---|
| 1 | 大阪出張 新幹線代 | 承認待ち |
| 4 | プリンタートナー | 承認待ち |
| 6 | 福岡出張 航空券 | 承認待ち |
| 8 | 電車代（研修会場） | 承認待ち |

### 2. 複数の条件
```powerfx
Filter(経費申請, 区分 = "交通費" && 金額 >= 5000)
```
| 書き方 | 意味 |
|---|---|
| `&&`（または And） | かつ |
| `||`（または Or） | または |
| `条件1, 条件2` | 条件を , で並べても「かつ」 |
交通費4件のうち、5000円以上は ID1（28,400）と ID6（41,200）の2件。

### 3. ドロップダウンと連動させる
Dropdown1 の選択肢：すべて／承認待ち／承認済み／差し戻し
```powerfx
Filter(経費申請, Dropdown1.Selected.Value = "すべて" || ステータス = Dropdown1.Selected.Value)
```
各行について、次のどちらかが成り立てば残ります。
| 選んだもの | 左の条件（すべて？） | 右の条件 | 結果 |
|---|---|---|---|
| すべて | **常に true** | — | 全10件 |
| 承認待ち | false | ステータスが承認待ちの行だけ true | 4件 |
| 差し戻し | false | ステータスが差し戻しの行だけ true | 2件 |
「すべて」のときは左側が常に true なので、どの行も残る ── という仕組みです。

### 4. 比較の注意
- 文字は " " で囲む。数値は囲まない（`金額 >= 5000`）
- 等しいは `=`（1つ）

@pitfalls
- **数値を " " で囲む** `金額 >= "5000"` → 「数値とテキストは大小比較できません」
- **Dropdown1.Selected だけ** → レコード。値は `.Value`
- **「すべて」の処理を忘れる** → 「すべて」を選ぶと0件になる
- **= と == ** Power Fx の比較は = 1つ

@steps ap4a
1. Gallery1 の Items を Filter(データ, 条件) に書き換える
2. データは 経費申請、条件は ステータス = "承認待ち"
3. 4件になったら採点

@steps ap4b
1. 条件は2つ：区分 = "交通費"、金額 >= 5000（数値は " " なし）
2. && でつなぐか、, で並べる
3. 2件になったら採点

@steps ap4c
1. 条件は「ドロップダウンが『すべて』」または「ステータスがドロップダウンの値と同じ」
2. ドロップダウンの値は Dropdown1.Selected.Value
3. Filter(経費申請, Dropdown1.Selected.Value = "すべて" || ステータス = Dropdown1.Selected.Value) の形にする
4. プレビューでドロップダウンを切り替えて、件数が 10 → 4 → … と変わることを確認して採点

@@lesson ap5
@image
検索ボックスは、ほとんどの業務アプリに付いている機能です。入力した文字を **含む** 行を探す **Search** と、入力した文字で **始まる** 行を探す **StartsWith** の2つを使い分けます。

なぜ2つあるのか。SharePoint のような大きなデータでは、Search（含む）は **すべてのデータを調べられない** ことがあるからです（委任の問題、第13回）。どちらでも困らない場面では StartsWith を選ぶのが、実務での安全な選択です。

@detail
### 1. Search ― 含む
```powerfx
Search(経費申請, TextInput1.Text, "件名", "申請者")
```
| 部分 | 意味 |
|---|---|
| 経費申請 | 探すデータ |
| TextInput1.Text | 探す文字 |
| "件名", "申請者" | 探す列（**列名を " " で囲む**） |
| 入力 | 結果 |
|---|---|
| （空） | 全10件 |
| 田中 | 申請者が田中 誠の2件（ID1・3） |
| 出張 | 件名に「出張」を含む2件（大阪出張・福岡出張） |
- 指定した列の **どれか** に含まれていれば残る
- 大文字小文字は区別しない
- 入力が空なら全件

### 2. StartsWith ― で始まる
```powerfx
Filter(経費申請, StartsWith(件名, TextInput1.Text))
```
| 入力 | 結果 |
|---|---|
| タクシー | 「タクシー代（顧客訪問）」の1件 |
| 大阪 | 「大阪出張 新幹線代」の1件 |
| 出張 | **0件**（「出張」で始まる件名はない） |
StartsWith は条件の関数なので、Filter の中で使います（列名は " " なし）。

### 3. 絞り込みと検索を組み合わせる
「ステータスで絞り込んだ結果の中から、さらに検索する」には、**内側に Filter、外側に Search** と重ねます。
```powerfx
Search(
    Filter(経費申請, Dropdown1.Selected.Value = "すべて" || ステータス = Dropdown1.Selected.Value),
    TextInput1.Text, "件名", "申請者"
)
```
| ステップ | 例：承認待ち・「出張」 |
|---|---|
| ① Filter | 承認待ちの4件 |
| ② Search | その中で「出張」を含む → 大阪出張・福岡出張 の2件 |
関数の結果（表）を、別の関数の1つ目の引数に渡す ── これは Sort でも同じです。

@pitfalls
- **Search の列名を " " で囲み忘れる** → エラー（Search は列名を文字で指定）
- **StartsWith の列名を " " で囲む** → 逆にこちらは囲まない（Filter の中の普通の列）
- **Search で「始まる」を期待する** Search は「含む」
- **組み合わせの順番** 外側の関数が最後に実行される

@steps ap5a
1. Search(データ, 探す文字, "列1", "列2") の形
2. データは 経費申請、探す文字は TextInput1.Text、列は "件名" と "申請者"
3. プレビューで「田中」「出張」と入力して結果を確かめてから採点

@steps ap5b
1. 「件名が入力した文字で始まる」は StartsWith(件名, TextInput1.Text)
2. それを Filter(経費申請, …) の条件にする
3. 「タクシー」で1件になることを確かめてから採点

@steps ap5c
1. まず ap4c と同じ Filter（ドロップダウンでの絞り込み）を書く
2. その Filter(…) 全体を、Search の1つ目の引数にする
3. Search の残りの引数は TextInput1.Text, "件名", "申請者"
4. カッコの対応に注意して採点

@@lesson ap6
@image
一覧の **並び順** は、使いやすさを大きく左右します。「新しい申請が上」「金額の大きいものが上」── こうした並べ替えを Sort で指定します。

さらにトグル（オン・オフのスイッチ）と組み合わせれば、**利用者が並び順を切り替えられる** ようになります。If の中で SortOrder を切り替えるのがポイントです。

@detail
### 1. Sort の形
```powerfx
Sort(経費申請, 金額, SortOrder.Descending)
```
| 部分 | 意味 |
|---|---|
| 経費申請 | 並べ替えるデータ |
| 金額 | 何で並べるか（列名、または式） |
| SortOrder.Descending | 大きい順（降順）。省略すると小さい順（昇順） |
| 順位 | 件名 | 金額 |
|---|---|---|
| 1 | 福岡出張 航空券 | 41,200 |
| 2 | 大阪出張 新幹線代 | 28,400 |
| 3 | プリンタートナー | 12,800 |

### 2. SortByColumns ― 列名を文字で指定
```powerfx
SortByColumns(経費申請, "申請日", SortOrder.Descending)
```
- 列名を **" " で囲む**
- `"列1", 順序, "列2", 順序` と並べると、2つ目のキーで並べられる
- SharePoint などで **委任しやすい** 書き方（大量データ向き）

### 3. トグルで順序を切り替える
```powerfx
Sort(経費申請, 金額, If(Toggle1.Value, SortOrder.Descending, SortOrder.Ascending))
```
| Toggle1 | If の結果 | 並び |
|---|---|---|
| オン（true） | SortOrder.Descending | 金額の大きい順 |
| オフ（false） | SortOrder.Ascending | 金額の小さい順 |
If は「条件が true なら2つ目、false なら3つ目」を返す関数です。値だけでなく、**並べ替えの向きのような設定値** を切り替えるのにも使えます。

### 4. 絞り込み・検索と組み合わせる
```powerfx
Sort(Filter(経費申請, ステータス = "承認待ち"), 申請日, SortOrder.Descending)
```
内側で絞り込み、外側で並べ替え。

@pitfalls
- **SortOrder の書き方** `SortOrder.Descending`（降順）／`SortOrder.Ascending`（昇順）。"降順" のような日本語は不可
- **Sort の列名を " " で囲む** Sort は囲まない、SortByColumns は囲む
- **If の true/false の順番** If(条件, true のとき, false のとき)
- **並べ替えた後に Filter** 順番はどちらでも結果は同じだが、件数の多いデータは先に絞る方が速い

@steps ap6a

2. データ 経費申請、列 金額、向き SortOrder.Descending
3. 一番上が「福岡出張 航空券」になったら採点

- 必要な項目が全部入力されるまで **送信ボタンを押せなく** する

どれも、色・表示・操作可否のプロパティに **If や Switch の数式** を書くだけで実現できます。

@detail
### 1. 色・表示・操作可否のプロパティ
| プロパティ | 値の例 | 効果 |
|---|---|---|
| Color | Color.Red、RGBA(255,0,0,1) | 文字の色 |
| Fill | Color.LightGray | 背景の色 |
| Visible | true / false | false で非表示 |
| DisplayMode | DisplayMode.Edit / .Disabled / .View | 操作できる / 灰色で押せない / 表示のみ |

### 2. Switch ― 値ごとに分ける
```powerfx
Switch(ThisItem.ステータス,
    "承認済み", Color.Green,
    "差し戻し", Color.Red,
    Color.Orange
)
```
| ステータス | 文字の色 |
|---|---|
| 承認済み | 緑 |
| 差し戻し | 赤 |
| 承認待ち（どれでもない） | オレンジ |
`Switch(調べる値, 値1, 結果1, 値2, 結果2, その他)`。最後の1つは「どれにも当てはまらないとき」。ギャラリーの中の部品なので ThisItem を使います。

### 3. Visible ― 条件で表示・非表示
```powerfx
Gallery1.Selected.ステータス = "承認待ち"
```
Visible には **true か false になる式** をそのまま書けます（If を書かなくてよい）。
| 選んだ申請 | 式の結果 | ボタン |
|---|---|---|
| 1行目（承認待ち） | true | 表示 |
| 2行目（承認済み） | false | 非表示 |

### 4. DisplayMode ― 未入力なら押せない
```powerfx
If(IsBlank(txt件名.Text) || IsBlank(txt金額.Text), DisplayMode.Disabled, DisplayMode.Edit)
```
| 件名 | 金額 | ボタン |
|---|---|---|
| 空 | 空 | 押せない（灰色） |
| 文房具 | 空 | 押せない |
| 文房具 | 800 | 押せる |
- `IsBlank(値)`：空なら true
- `||`：どちらか一方でも空なら Disabled

### 5. If と Switch の使い分け
| 場面 | 向いている関数 |
|---|---|
| 1つの値を、いくつかの値と比べる | Switch |
| 条件がバラバラ（金額 > 1万、日付が古い…） | If（条件と結果を何組でも並べられる） |

@pitfalls
- **Switch の最後の「その他」を忘れる** → どれにも当てはまらないとき空白（色なし）
- **Visible に "true" と文字で書く** → true（" " なし）
- **DisplayMode の書き方** DisplayMode.Disabled（"Disabled" ではない）
- **&& と || の取り違え** 「どちらか空なら押せない」は ||

アプリには **「ちょっと覚えておく」** 場所が必要です。

- 選んだ申請の件名を、別の画面でも使いたい

@detail
### 1. 3種類の覚え方
| 種類 | 入れ方 | 使える範囲 | たとえ |
|---|---|---|---|
| グローバル変数 | `Set(名前, 値)` | アプリ全体 | 共有のホワイトボード |
| コンテキスト変数 | `UpdateContext({名前: 値})` | その画面だけ | 机の上のメモ |
| コレクション | `Collect(名前, レコード)` | アプリ全体 | 小さな表 |

| | 書くプロパティ | 例 |
|---|---|---|
| 表示の式 | Text、Items、Color、Visible… | 値を計算して返すだけ |
| 動作の式 | OnSelect、OnVisible、OnStart… | **何かを変える**（変数・データ・画面） |


| 操作 | カートの中身 |

| もう一度押す | コーヒー豆 1500 1 ／ コーヒー豆 1500 1 |

ここまでの関数は、データを **読むだけ** でした。業務アプリの本番は、データを **書き込む** ことです。

- 承認ボタンで、申請のステータスを「承認済み」に **更新**

@detail
### 1. Patch で更新
```powerfx
Patch(経費申請, Gallery1.Selected, {ステータス: "承認済み"})
```
| 部分 | 意味 |
|---|---|
| 経費申請 | 書き込む先のデータソース |
| Gallery1.Selected | **どの行を**（選んでいる申請） |
| {ステータス: "承認済み"} | **何を変えるか**（変える列だけ書く） |
| ID | 件名 | ステータス（前） | → | ステータス（後） |
|---|---|---|---|---|
| 1 | 大阪出張 新幹線代 | 承認待ち | | **承認済み** |
他の列（件名・金額…）はそのまま。

### 2. Patch で追加（Defaults）
```powerfx
Patch(経費申請, Defaults(経費申請), {
    件名: txt件名.Text,
    金額: Value(txt金額.Text),
    区分: drp区分.Selected.Value,
    ステータス: "承認待ち",
    申請者: User().FullName
})
```

- 金額の列は数値なので `Value()` で入力を数値に変換
- ドロップダウンの値は `.Selected.Value`
- ID は自動で振られる

| ID | 件名 | 金額 | 区分 | ステータス | 申請者 |
|---|---|---|---|---|---|
| 11 | 文房具 | 800 | 消耗品費 | 承認待ち | 山田 太郎 |

### 3. Remove / RemoveIf で削除

```powerfx
Remove(経費申請, Gallery1.Selected)                    // 選んだ1件
```

### 4. 保存の後にメッセージ

| 部分 | 意味 |

| ScreenTransition.Fade | 切り替えの効果（フェード）。省略可 |

業務アプリでは日付の計算がよく出てきます。「申請から何日たった？」「支払予定日は30日後」「今月の申請だけ」…。

Power Fx には Excel とよく似た日付の関数がそろっています。日付は内部では「数」のように扱えるので、**足したり引いたり** できます。ポイントは、計算は日付のまま行い、**表示するときに Text で書式を整える** ことです。

> 演習の「今日（Today）」は 2026年6月15日に固定しています。

@detail
### 1. 日付の関数
| 関数 | 例 | 結果 |
|---|---|---|
| Today() | Today() | 2026/6/15 |
| Date(年, 月, 日) | Date(2026, 5, 1) | 2026/5/1 |
| Year / Month / Day | Month(Date(2026,5,7)) | 5 |
| DateAdd(日付, 数, 単位) | DateAdd(Date(2026,5,7), 30, TimeUnit.Days) | 2026/6/6 |
| DateDiff(開始, 終了, 単位) | DateDiff(Date(2026,5,7), Today()) | 39 |

### 2. 経過日数
```powerfx
ThisItem.ステータス & "（" & DateDiff(ThisItem.申請日, Today()) & "日経過）"
```
| 申請日 | DateDiff(申請日, Today()) | 表示 |
|---|---|---|
| 2026/5/7 | 39 | 承認待ち（39日経過） |
| 2026/5/8 | 38 | 承認済み（38日経過） |
| 2026/6/9 | 6 | 差し戻し（6日経過） |
DateDiff の単位を省略すると「日」。月なら TimeUnit.Months。

### 3. ○日後の日付
```powerfx
"支払予定: " & Text(DateAdd(Gallery1.Selected.申請日, 30, TimeUnit.Days), "yyyy/mm/dd")
```
| 申請日 | 30日後 | 表示 |
|---|---|---|
| 2026/5/7 | 2026/6/6 | 支払予定: 2026/06/06 |
| 2026/6/2 | 2026/7/2 | 支払予定: 2026/07/02 |
月をまたいでも自動で計算されます。

### 4. 月で絞り込む
```powerfx
Filter(経費申請, Month(申請日) = 5)
```
5月の申請7件が残ります。（ただし SharePoint の大量データでは委任の問題あり → 第13回で書き換え方を学ぶ）

### 5. 日付の書式
| 書式 | 結果（2026/5/7） |
|---|---|
| "yyyy/mm/dd" | 2026/05/07 |
| "yyyy年m月d日" | 2026年5月7日 |
| "m/d (ddd)" | 5/7 (木) |
mm は2桁の月、m は1桁でもそのまま。`hh:mm` のように時の後に書いたときだけ mm は「分」になります。

@pitfalls
- **日付を文字にしてから計算** → 計算は日付のまま。表示のときだけ Text
- **DateDiff の順番** DateDiff(古い日, 新しい日) で正の数
- **DateAdd の単位** TimeUnit.Days / TimeUnit.Months（"Days" ではなく TimeUnit.）
- **カッコの全角・半角** 表示する「（」は全角でよいが、関数のカッコは半角

3. 1行目が「承認待ち（39日経過）」になったら採点

@steps ap12b

2. Filter(経費申請, その条件)
3. 7件になったら採点（委任の警告が出るのは正常。次の第13回で直し方を学ぶ）

@steps ap12c

@@lesson ap13
@image
最後は、アプリを **本番で使うときの落とし穴と、仕上げ** です。

いちばん大事なのは **委任（Delegation）**。データが少ない練習では問題なく動いていたアプリが、本番の SharePoint に3000件たまった頃に **「検索しても古い申請が出てこない」** という、気づきにくい不具合を起こすことがあります。原因と書き換え方を知っておけば防げます。

@detail
### 1. 委任とは
Power Apps は、データの処理を **データソース側（SharePoint など）に任せる（委任する）** ことができます。
| | 委任できる式 | 委任できない式 |
|---|---|---|
| 処理する場所 | SharePoint のサーバー | 自分のスマホ・PC |
| 対象のデータ | **全件** | **先頭の500件（設定で最大2000件）だけ** |
| 結果 | 正しい | 2001件目以降が無視される |
委任できない式でも **エラーにはならず、黙って一部だけで処理する** のが怖いところです。Studio では黄色の ⚠ と青い二重下線で警告されます（このアプリでも黄色の「委任の警告」が出ます）。

### 2. SharePoint で委任できる・できないの例
| 委任できる | 委任できない |
|---|---|
| `=`, `<>`, `<`, `>`, `<=`, `>=` | Search、`in`（部分一致） |
| `&&`, `||`, `!` | 条件の中で Len・Left・Month・Year などの関数 |
| StartsWith | 条件付きの CountRows・Sum など |

### 3. 書き換えの例：月で絞る
委任できない（Month 関数を条件に使っている）：
```powerfx
Filter(経費申請, Month(申請日) = 5)
```
委任できる（比較演算子だけ）：
```powerfx
Filter(経費申請, 申請日 >= Date(2026, 5, 1) && 申請日 < Date(2026, 6, 1))
```
| | 結果（このデータ） | 3000件のとき |
|---|---|---|
| Month(…) = 5 | 7件 | 先頭2000件の中の5月分しか出ない |
| 日付の範囲 | 7件 | **全件の中の5月分** |
「5月1日以上、6月1日より前」と書くのがコツです（5月31日 <= と書くと、時刻付きのデータで漏れることがあるため）。

### 4. 検索の書き換え
| 委任できない | 委任できる |
|---|---|
| `Search(経費申請, TextInput1.Text, "件名")` | `Filter(経費申請, StartsWith(件名, TextInput1.Text))` |
「含む」ではなく「で始まる」になりますが、全件から正しく探せます。

### 5. 公開と共有
- **保存 → 公開**：公開するまで、利用者には古いバージョンが表示される
- **共有**：利用者を追加し、**データソース（SharePoint リスト）の権限も** 付与する
- 利用者はスマホの Power Apps アプリ、ブラウザ、Teams から使える

### 6. Power Automate との連携
メール送信・上司への承認依頼・毎朝の自動処理は **Power Automate** の得意分野です。
例：申請ボタン → フローを呼び出す → 上司に承認依頼 → 結果で SharePoint のステータスを更新

@pitfalls
- **少ないデータでしかテストしない** → 委任の問題に気づかない。設定でデータ行の制限を小さくして試すと見つけやすい
- **警告を無視する** 黄色の三角は「将来、結果が欠ける」サイン
- **保存しただけで公開しない** → 利用者の画面が変わらない
- **アプリだけ共有してデータの権限を忘れる** → 利用者のアプリでデータが表示されない

@steps ap13a
1. Month(申請日) = 5 を、比較演算子だけの条件に置き換える
2. 「2026年5月1日 以上」は 申請日 >= Date(2026, 5, 1)
3. 「2026年6月1日 より前」は 申請日 < Date(2026, 6, 1)
4. 2つを && でつないで Filter に入れる。7件のまま、委任の警告が消えたことを確認して採点
